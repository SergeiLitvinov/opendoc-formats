# Аудит библиотеки

Проверены архитектурные границы, нативное редактирование, импорт/экспорт, полнота
исходных форматов, ресурсы, типизация, корпус документов, зависимости, лицензии,
установка пакетов и автоматизация публикации.

## Самостоятельность

Отдельный пакет со своими версиями и выпусками. **OpenDoc Model 0.14.0 обязателен**;
полная автономность не заявляется. Единственная обязательная зависимость — официальная
модель OpenDoc. Проверка AST и установленного wheel подтверждает отсутствие импортов
приложения и соседнего дерева исходников. Базовая установка не требует движков форматов.

## Улучшения относительно предыдущей версии

Стандартный `pdf` сокращён до одного PyMuPDF. Альтернативные pypdf/pdfplumber/
pdf2docx и их цепочки ставятся только явными узкими профилями. Проверка файла
и Unicode Info metadata работают на каждом одиночном профиле без второго parser.
Собственные PDF→DOCX/table алгоритмы до равноценной приёмки остаются OF17.

Конечный DOCX paragraph indent исправлен для трёх осей: прямые объявления,
наследование, defaults, правка/удаление и нативная правка Word. Полные страницы
собственного примера совпали с оригиналом и независимыми native references
после двух циклов. Условный каскад, before/after/keep flags и таблицы остаются C05.

Файловая инспекция принимает выбранный бюджет в ImportOptions. Собственный PPTX
35 slides/6720 runs и его Model JSON сохраняют метрики, inventory и text flow
при 200000 узлах; обычный лимит и отдельные квоты дают структурированный отказ.
Сохранены native PDF/HTML/LaTeX scopes; SHA256 до/после, ранняя/поздняя отмена,
изменение источника и явная частичная PDF-инспекция проверены отдельно.
Внутренние лимиты каждого декодера остаются задачей C-LIMIT-01.

DOCX использует общий LineSpacing: прямое значение, named/default inheritance,
правка, удаление и сравнение Model приняты без собственной схемы. Полные страницы
собственного Word-примера совпали с оригиналом после двух циклов; общие правки,
удаление, style edit и docDefaults совпали с независимыми нативными эталонами
при Poppler 96 dpi. Стиль и удаление прошли два последующих нативных цикла.
Передача выбранного бюджета в codec и неизвестные поля проверены отдельно;
межформатная семантика интервала остаётся расположенным LOSS.


Выбранный бюджет модели передаётся во все встроенные нативные экспортёры,
полнодокументные операции integration/outline/anchors, подготовку шрифтов,
частное цветовое представление и HTML/PDF renderer. Собственный PPTX сохраняет
точный текст через два нативных цикла с 200000 узлов; все шесть нативных форматов
принимают большую модель с 300000 и сохраняют текст. Частная копия большого DOCX
принимается HTML/PDF/PPTX с 500000, не меняя исходную модель. Квота при подготовке,
после увеличения цветового представления и в стороннем writer адресно отклоняется,
прежнее назначение сохраняется. Это приёмка бюджета, не нативной компоновки.

Цвет DOCX хранится прямой декларацией; общий API OpenDoc разрешает наследование
из defaults и именованных стилей. Правки и удаление цвета и ссылок на стили
проверены через два полных цикла. HTML/PDF/PPTX воспроизводят унаследованный RGB
в отдельном представлении, не меняя исходную модель. Правила интервала
auto/atLeast/exact удерживаются с величиной; непредставимые изменения и неизвестные
объявления адресно отклоняются. Word подтвердил два цикла и нативную правку
собственного шестипараграфного примера: полные страницы совпали при Poppler 96 dpi.
Детали и границы — в [профиле компоновки DOCX](../guide/docx-layout.md).

Прямые DOCX table indentation и tab stops используют общий TableIndent/TabStops
API OpenDoc 0.14.0, без новых зависимостей. Два полных DOCX/JSON цикла,
правка и удаление проверены собственными fixtures. Word 16.0 build 16.0.17932
подтвердил 30 pt и 396 pt/right/line; Poppler 96 dpi даёт одинаковые полные
страницы с оригиналом. Нативная правка до 12 pt и 296 pt/center/dot выдерживает
следующий публичный цикл. Unsupported source имеет native XPath, непредставимые
правки отказывают до публикации, межформатные потери адресны.
Полный inherited/conditional cascade и произвольное оформление этим не закрыты.


Адаптер использует OpenDoc Model 0.14.0; официальный wheel проверен целиком,
MIT LICENSE сохранён, остальные зависимости не изменились. Модель предоставляет
отдельный контракт измеренного текстового потока. Нативная PDF-инспекция
формирует профиль извлечённого слоя с явными лимитами и неизвестными состояниями;
полный инвентарь объектов из него не следует. Инспекция работает без pypdf.

Аудит AcroForm выявляет неподдержанную иерархию и поля без widgets по исходным
адресам. Строковые значения по умолчанию поддерживают явную правку и удаление.
Повторные widgets сохраняют разные нативные объекты и связь со страницами.
Полная иерархия полей остаётся в [TODO](todo.md); детали — в
[улучшениях версии](changelog.md).

История растровой замены проверена через два полных PDF/JSON цикла,
перестановку и удаление. Происхождение остаётся декларацией; текущие targets
измеряются заново. Повреждённая и устаревшая история адресно диагностируется.
Автоматическая карта SVG→PNG подтверждена с измеренными target resources,
двумя форматными циклами и сравнением итоговых пикселей, включая прозрачность.
Новых зависимостей нет. Композиция явных отношений между вхождениями проверена
через два PDF/JSON цикла, перестановку, удаление и отказ по качеству; декларативные
split/merge образуют связанные группы. Неизвестная связь остаётся неизвестной,
потери не превращаются в semantic, intermediate resource handles не копируются
в target. Полное доказательство связи произвольных файлов остаётся открытым.

Публикация каталога повторяет временные Windows access/sharing failures не более
пяти раз на операцию (суммарная задержка 0,75 секунды). Постоянная ошибка до
фиксации результата восстанавливает прежний каталог. Если очистка sibling backup
не удалась после фиксации, новый результат остаётся опубликованным, а журнал
указывает оставшийся backup; ложный отказ после успешной публикации исключён.

## Воспроизводимая приёмка

`ruff check`, строгий `mypy` публичных модулей, `tools.audit`, полный `pytest`,
`tools.docs check`, `tools.release check`, `twine check` и изолированный
`tools/package_smoke.py` — обязательные проверки CI. Linux: Python 3.11/3.12/3.13;
Windows: 3.12. На Linux 3.12 устанавливается LibreOffice для реального преобразования.
Fixtures описаны в [описании корпуса](corpus.md); нативные проверки — в `tests/native`.
Ссылки навигатора показывают связь с тестами, а не процент покрытия.

## Границы заключения

Корпус не доказывает полной поддержки спецификаций и не заменяет приёмку Office.
Неизменённые части DOCX сохраняются побайтно, но сжатый контейнер может отличаться.
PDF восстанавливает структуру эвристически. Отмена проверяется между вызовами движка;
текст/PNG и выход LibreOffice ограничиваются после его работы, не внутри его памяти.
Профиль LibreOffice не является файловой/сетевой песочницей. OCR и качество preview
определяет потребитель. [Подтверждённые задачи](todo.md) и [исследования](research.md)
описывают дальнейшую область развития без обещания полной спецификации.
Точная [матрица исходного импорта](../guide/format-audit.md) различает чтение,
сохранение оригинала и экспорт. LaTeX-читателя нет; EPUB/PPTX имеют подтверждённые
потери, воспроизводимые в `tests/test_source_coverage.py`.

Лицензионный вывод: собственный код и OpenDoc — MIT; полный набор движков содержит
AGPL, MPL и компоненты с отдельными условиями. Конкретные профили распространения
разобраны в [лицензионном аудите](licenses.md), все записи lockfile — в
[реестре зависимостей](../reference/dependencies.md).
