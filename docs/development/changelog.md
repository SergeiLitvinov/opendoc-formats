# Улучшения версии

## 0.4.0 — улучшения относительно 0.3.0

- Обязательная модель обновлена до официального `opendoc-model` 0.3.0;
  импорты используют `opendoc_model`, включая примеры, тесты и изолированную установку CI.
- Проверка и очистка исходного MathML при HTML-экспорте выполняются стандартной
  библиотекой Python без lxml. DTD, объявления сущностей и чужие элементы отклоняются;
  обработчики событий и активные ссылки удаляются. Преобразование OMML остаётся
  отдельным маршрутом с собственными требованиями к движку.

## 0.3.0 — улучшения относительно 0.2.0

- Нативный DOCX: неизменяемые снимки частей, абзацев, runs и таблиц; транзакционные
  правки по исходным ID и диапазонам, вставка абзацев и spanning rows, сохранение стилей.
- PDF-контекст: текст и геометрия страниц, ограниченный PNG-рендер и кэш,
  фактический масштаб для координат OCR, различимые ошибки и закрытие ресурсов.
- Офис → PDF через отдельный профиль LibreOffice, таймаут и отмену дерева процессов,
  проверку результата и атомарную публикацию. OCR и политика приложения остаются у потребителя.
- Сборка стандартных DOCX-ресурсов в официальной модели OpenDoc без схемы приложения.
- Extra `pdf-text` для минимального текстового маршрута; ленивость новых движков.
- Исправлены нулевая прозрачность заливки/обводки PDF и настройки очень маленьких страниц.
- Расширены типизация, корпус реальных документов, изолированная приёмка пакета и CI.
- Запросы OF01–OF05 закреплены у библиотеки: подтверждённый пробел PDF-векторного экспорта
  описан конечной задачей; непроверенные направления отделены в исследования.

OpenDoc Model остаётся единственной обязательной зависимостью. Новые API не раскрывают
объекты движков или XML. Полная поддержка спецификаций форматов не заявляется.
