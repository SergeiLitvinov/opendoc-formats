# Улучшения версии

## 0.19.0 — улучшения относительно 0.18.0

- PDF заполняет общий `PageGeometry` с отдельными MediaBox/CropBox и поворотом.
  DocumentPage width/height описывают media до поворота; viewport остаётся отдельным.
- Native writer восстанавливает исходные области вместо их замены размером crop.
  Поддержаны ненулевые/отрицательные начала, все четвертьобороты, typed crop/rotation
  правки и явное удаление. Геометрия и RGB viewport совпадают в двух PDF/JSON циклах.
- Source coordinates общего контракта задаются x=PDF x, y=-PDF y; outline points
  согласованы с PageGeometry. Legacy JSON без известных MediaBox не получает
  выдуманной геометрии и сохраняет прежний профиль записи.
- Ссылки layout writer-а сдвигаются вместе с содержимым. Неизвестные null points
  сохраняются неизвестными, без backend default/NaN; page mapping и repagination
  получают честную диагностику.
- Дополнительных зависимостей нет; opendoc-model 0.7.2 и весь граф пакетов прежние.

## 0.18.0 — улучшения относительно 0.17.0

- PDF оглавление заполняет общий `Outline`: иерархия, устойчивые IDs, sibling
  order, назначения page/external, source points и zoom. Native данные сохранены.
- Writer создаёт реальные закладки; page points учитывают crop/rotation,
  paragraph anchors следуют реальному потоку страниц. Безопасные URI сохраняются,
  неподдержанные назначения остаются без перехода с located LOSS.
- Старые JSON мигрируют однократно; типизированные правки и удаление не заменяются
  прежним native extension. Неизвестные данные сохраняются.
- Геометрия страницы фиксируется до анализа таблиц: обрезанные повёрнутые страницы
  больше не получают изменённый backend-ом размер. Точки записываются в native PDF
  coordinates, без ошибки 270-градусного TOC преобразования.
- Два реальных PDF/JSON цикла проверены для четырёх поворотов, crop, иерархии,
  URI и zoom; правки, удаление и переходы на последующие страницы проверены отдельно.
  Новых зависимостей нет, opendoc-model 0.7.2 и остальные пакеты не изменены.

## 0.17.0 — улучшения относительно 0.16.1

- PDF writer поддерживает произвольный поворот, shear и отражение растра,
  нативную обрезку без пересэмплирования. Конечный clip reader возвращает
  геометрию и ImageCrop; два PDF/JSON цикла точно сохраняют RGB pixels.
- Inline-изображения следуют фактическому потоку и страницам Story, включая
  выравнивание и колонтитулы. Paragraph anchor имеет диагностируемый flow fallback;
  сложный wrapping, эффекты и исходный paint order остаются вне этого профиля.
- Поворот рамки без native matrix согласован с DrawingML: по часовой стрелке
  вокруг центра, включая 90 градусов. Нативные PDF matrices сохраняют свои оси.
- Добавлены проверки crop/affine/inline bounds и PNG dimensions; отказ сохраняет
  прежний файл. Независимый Form-reference проверяет геометрию и interior pixels.
- Обязательная модель обновлена до официальной MIT opendoc-model 0.7.2:
  общий Outline, исправления лимитов и непрозрачных данных. Публичный JSON API
  сохраняет новый контракт. Другие зависимости не изменены; новые не добавлены.

## 0.16.1 — улучшения относительно 0.16.0

- DOCX заполняет общий WidthMeasure: абсолютная ширина в points, доля области
  страницы/таблицы, auto и unspecified. Нулевая и отсутствующая ширина различаются.
- Неизменённые значения сохраняют исходную OOXML запись; типизированные правки
  и удаление имеют приоритет. Дробные значения не округляются writer-ом.
- Публичное чтение прежних JSON мигрирует native widths до редактирования;
  исходный JSON остаётся неизменным. Поддерживается прежний width_twips.
- Два цикла проверены по модели/XML; Word подтвердил прежнюю геометрию 10/80/10
  и тип/значение изменённых предпочтений с учётом собственной дискретности Word.
- Дополнительных зависимостей нет, состав lockfile не изменён.

## 0.16.0 — улучшения относительно 0.15.5

- DOCX заполняет формальную роль Heading из нативных outline levels,
  наследуемых стилей и defaults; оформление не используется как эвристика.

  роли и производные стили при восстановлении исходного package.

- Обязательная модель обновлена до официального opendoc-model 0.6.0:
  типизированные preferred widths, семантика таблиц и page geometry доступны
  в общем контракте. Дополнительных обязательных зависимостей модель не добавляет.
  JSON v1/v2 и нативные профили проверяются с обновлённым пакетом.

## 0.15.0 — улучшения относительно 0.14.0

  unknown DC fields диагностируются. Новых зависимостей нет.
- OF09 закрыта для опубликованного конечного EPUB writer profile: roundtrip,
  ресурсы/ссылки/metadata, EPUBCheck, лимиты, отмена и атомарная публикация проверены.
  Полнота семантики исходного EPUB остаётся отдельной задачей OF08.

## 0.11.2 — улучшения относительно 0.11.1

- EPUB сохраняет оригинальные container/OPF/nav/NCX как inert XML attachments:
  точные байты, имена частей архива и resource IDs проверяются через JSON.

## 0.11.1 — улучшения относительно 0.11.0

  Поддержка nav и прочих неподдержанных item types не заявляется. Новых зависимостей нет.

## 0.11.0 — улучшения относительно 0.10.0

- EPUB импортирует standalone images и inline SVG в исходном порядке.
  SVG сохраняется как безопасный vector resource с opaque оценкой, без заявления
  о редактируемой модели фигур; опасные атрибуты и элементы диагностируются.
- Исходные font/audio/video assets сохраняются как inert attachments с проверенным
  ресурсом в ledger и точными байтами через JSON. Они не активируются как шрифты
  и не проигрываются; HTML export явно сообщает о невоссозданной семантике.
- Внешний URL и ссылка на файл другого media type не превращаются в локальное
  изображение. Коллизии SVG ID не перезаписывают manifest assets; одинаковые
  безопасные SVG используют общий ресурс. Новых зависимостей нет.

## 0.10.0 — улучшения относительно 0.9.1

  при вложенном расположении OPF. JSON и HTML экспорт проверены. Новых зависимостей нет.

## 0.8.2 — улучшения относительно 0.8.1

- DOCX записывает частичный отчёт о сложных объектах: комментариях, правках,
  content controls, полях, text boxes/WordArt, SmartArt/OLE и защите документа.
  `opaque` требует подтверждённого сохранения XML-фрагмента или части пакета;
  пропущенный объект отмечается `lost`. XPath, ID, исходная часть и причина
  сохраняются через JSON; внешняя OLE-связь не выдаётся за перенесённый payload.
- Исправлен регистр Office `OLEObject`: исходный run теперь удерживает XML объекта,
  его часть и связь сохраняются при DOCX → JSON → DOCX. Namespace чужого `ins`
  не засчитывается как поддержка Word revisions. Inventory обозначен как учёт,
  а не подтверждение сохранности каждого объекта.
- Новые зависимости не добавлены; полная семантика сложного DOCX остаётся задачей.

## 0.8.0 — улучшения относительно 0.7.2

- TXT получил конечный `TextProfile`: UTF-8/UTF-16 LE/BE/CP1251, BOM и newline policy.
  Исходный профиль и provenance сохраняются через JSON; проверен byte roundtrip,
  включая смешанные переводы строк, пустой текст и конечную пустую строку.
- Изменение поведения чтения: CP1251 без BOM теперь выбирается явно через
  `ImportOptions(txt_profile=TextProfile("cp1251"))`; молчаливое угадывание удалено.
  Неоднозначный/невалидный ввод получает machine reason, а непредставимый текст
  не заменяет прежний выходной файл. Стандартная запись остаётся UTF-8/LF без BOM.
- Новых зависимостей нет; закрыта задача конечного профиля кодировок TXT.

  блоков или без ресурса, медиа, встроенные объекты, скрипты и ресурсы шрифтов/медиа.
- Диагностика содержит машинную причину, адрес части книги и XHTML ID либо строку/колонку;
  provenance и issues проверены через JSON и повторный импорт. Оценка остаётся неполной.
- Дополнительные зависимости не добавлены; native EPUB продолжает работать без EbookLib/lxml.

## 0.7.1 — улучшения относительно 0.7.0

- Общий результат импорта включает предупреждения EPUB, PDF и пользовательских
  читателей, а также сохранённый через JSON отчёт OpenDoc о сохранности объектов.
- Добавлены `assessment_complete` и `lossless`: успешное чтение без предупреждений
  не выдаётся за подтверждение отсутствия потерь. Состояния opaque/visual/lost/rejected
  сохраняют машинную причину, источник и различимую степень потери.

## 0.7.0 — улучшения относительно 0.6.0

- PDF-векторные ресурсы экспортируются нативными командами: линии, кривые Безье,
  прямоугольники и четырёхугольники с координатами, цветами, прозрачностью и обводкой.
- Импорт сохраняет bbox, толщину, dash pattern, caps/joins, правило заливки и замыкание.
  PDF Story больше не пытается открыть эти ресурсы как растровые изображения.
- Для неподдержанного вектора используется заданный ограниченный PNG surrogate
  с диагностикой потери и provenance; без него экспорт отклоняется атомарно.
- Проверены точное совпадение пикселей, нулевая прозрачность, JSON, неизменность
  исходной модели, предел команд, предел surrogate и отмена перед публикацией.

## 0.6.0 — улучшения относительно 0.5.0

- PDF-профили разделены по маршрутам: `pdf-rich` (PyMuPDF), `pdf-layout` (pdfplumber),
  `pdf-docx` (pdf2docx). Прежний `pdf` сохранён для совместимости.
- Чтение модели PDF, геометрия, рендер и экспорт доступны без установки OpenCV,
  NumPy, python-docx, pdfplumber и pypdf через `pdf-rich`.
- Каждый профиль проверяется после установки wheel в отдельное окружение;
  лицензии и состав зависимостей каждого профиля приведены в документации.

## 0.5.0 — улучшения относительно 0.4.0

- Собственный EPUB-контейнер читает OPF, spine, EPUB 3 nav и EPUB 2 NCX без EbookLib
  и lxml, сохраняя существующий XHTML/CSS reader. `epub` устанавливает только BeautifulSoup
  и его зависимости. Прежний backend сохранён в `epub-ebooklib` и выбирается явно.
- Проверены совпадение семантики backend, метаданные, ссылки, изображения, стили,
  JSON roundtrip, запрет внешних/escaping ссылок и XML-сущностей.

## 0.4.0 — улучшения относительно 0.3.0

- Обязательная модель обновлена до официального `opendoc-model` 0.3.0;
  импорты используют `opendoc_model`, включая примеры, тесты и изолированную установку CI.
- Проверка и очистка исходного MathML при HTML-экспорте выполняются стандартной
  библиотекой Python без lxml. DTD, объявления сущностей и чужие элементы отклоняются;
  обработчики событий и активные ссылки удаляются. Преобразование OMML остаётся
  отдельным маршрутом с собственными требованиями к движку.

## 0.3.0 — улучшения относительно 0.2.0

- Нативный DOCX: неизменяемые снимки частей, абзацев, runs и таблиц; транзакционные
  правки по исходным ID и диапазонам, вставка абзацев и spanning rows, сохранение стилей.
- PDF-контекст: текст и геометрия страниц, ограниченный PNG-рендер и кэш,
  фактический масштаб для координат OCR, различимые ошибки и закрытие ресурсов.
- Офис → PDF через отдельный профиль LibreOffice, таймаут и отмену дерева процессов,
  проверку результата и атомарную публикацию. OCR и политика приложения остаются у потребителя.
- Сборка стандартных DOCX-ресурсов в официальной модели OpenDoc без схемы приложения.
- Extra `pdf-text` для минимального текстового маршрута; ленивость новых движков.
- Исправлены нулевая прозрачность заливки/обводки PDF и настройки очень маленьких страниц.
- Расширены типизация, корпус реальных документов, изолированная приёмка пакета и CI.
- Запросы OF01–OF05 закреплены у библиотеки: подтверждённый пробел PDF-векторного экспорта
  описан конечной задачей; непроверенные направления отделены в исследования.

OpenDoc Model остаётся единственной обязательной зависимостью. Новые API не раскрывают
объекты движков или XML. Полная поддержка спецификаций форматов не заявляется.
