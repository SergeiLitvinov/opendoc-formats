# Улучшения версии

## 0.26.0 — улучшения относительно 0.25.0

- Публичная нативная PDF-инспекция формирует общий TextFlowProfile OpenDoc и
  whitespace-normalized отпечаток извлечённого текстового слоя. Равный поток
  проходит бюджет правок 0; изменённый, частичный и недоступный — нет.
  Профиль не подтверждает OCR, порядок чтения, верстку или инвентарь объектов.
- Инспекция больше не требует pypdf: шифрование проверяет уже используемый
  PyMuPDF, а собственный ограниченный обход AcroForm считает уникальные полные
  имена, включая родительские узлы и поля без widgets. Данные вне профиля
  диагностируются как непроверенные, а не как нулевой счёт.
- Добавлена приёмка минимального установленного pdf-rich без pypdf. Пакет
  pypdf остаётся самостоятельным PDF-text движком; новых зависимостей нет.

## 0.25.0 — улучшения относительно 0.24.0

- Обязательная зависимость обновлена до официального opendoc-model 0.10.1.
  Полный SHA-256 пакета и MIT LICENSE проверены; остальные зависимости сохранены.
  Новый общий профиль измеренного текста доступен в модели. Его использование
  нативной PDF-инспекцией остаётся отдельной задачей; полный инвентарь объектов
  из наличия профиля не следует.
- Добавлен ограниченный аудит AcroForm Fields/Kids с адресной диагностикой
  иерархии, полей без widgets и неподдержанных свойств. Строковые default values
  текстовых полей сохраняются, редактируются и удаляются явно. Конфликт общих
  значений и превышение лимита приводят к отказу без замены предыдущего файла.
- Повторные widgets получают собственную связь со страницей: оптимизация PDF
  больше не объединяет разные вхождения. Два PDF/JSON цикла проверяют canonical
  поля, default values и отдельные нативные объекты. Полная иерархия остаётся в TODO.

## 0.24.0 — улучшения относительно 0.23.0

- Добавлена нативная запись URI links, Text notes, highlights и текстовых полей
  на подтверждённой исходной странице. Восемь вариантов размеров/поворотов
  проходят два PDF/JSON цикла относительно оригинала, canonical field/widget
  проверку и нативную правку с последующим циклом; typed edit/delete не возвращает backup.
- Основной текст и векторы извлекаются из несохраняемой копии без appearances;
  повторное открытие очищает native caches. Widget text больше не дублируется.
- Поддержанный одиночный script переносится как inert data. Неизвестные действия,
  геометрия и виды имеют отдельную диагностику. Полный C-PDF-01 остаётся в TODO.
  Новых зависимостей нет.

## 0.23.0 — улучшения относительно 0.22.3

- Обязательная зависимость обновлена до официального opendoc-model 0.9.1.
  Пакет проверен по SHA-256; MIT LICENSE и остальные зависимости не изменились.
- Модель предоставляет типизированный контракт карты исходных вхождений,
  представлений и результата с явными состояниями публикации. Вычисление карт
  и подтверждение нативных адресов адаптером остаются задачей C-MAP-01 / OF15;
  наличие контракта не означает полной реализации PDF-профиля.

## 0.22.3 — улучшения относительно 0.22.2

- PDF writer восстанавливает Unicode однозначных OpenType-лигатур по встроенному
  GSUB для собственного Story результата. Глифы, shaping и изображение сохраняются;
  собственный синтетический шрифт проверен по тексту и точному RGB-рендеру.
- Неоднозначные данные не угадываются, обработка ограничена; обязательная проверка
  текста и отказ без замены предыдущего файла сохранены. Новых зависимостей нет.
- Документация фиксирует границы профиля и конечные контракты PDF, карт объектов
  и оформления DOCX. Полная поддержка этих контрактов остаётся в TODO.

## 0.22.2 — улучшения относительно 0.22.1

- Читатель DOCX учитывает приоритет Latin theme reference над literal fallback
  на одном уровне каскада; отдельная ASCII family не заменяется hAnsiTheme.
  Прямые ссылки темы входят в direct fields, а доступные defaults участвуют
  в определении семейства. Собственный Calibri 12 bold сохраняется в Word
  через два публичных DOCX/JSON цикла. Unicode/RTL и перенос между системами
  с различными установленными шрифтами остаются в OF05.
- Добавлены регрессии каскада, отдельная нативная приёмка и документация.
  Зависимости и их лицензионный состав не изменены.

## 0.22.1 — улучшения относительно 0.22.0

- Поточный PDF writer не использует извлечённые glyph bounds как жёсткую
  ширину текста после подстановки шрифта. На собственной странице 240×200 pt
  полный текст совпадает с оригиналом в двух PDF/JSON циклах при всех четырёх
  поворотах. Изменение исходной компоновки имеет расположенный `pdf-text-layout` LOSS.
- До публикации проверяются нормализованные plain text occurrences в нативном
  результате, отдельно от колонтитулов. Пропуск имеет расположенный
  `pdf-text-content` ERROR и сохраняет предыдущий файл. Проверка ограничена
  по размеру и работе; новые зависимости не добавлены.

## 0.22.0 — улучшения относительно 0.21.0

- Обязательная модель обновлена до официального opendoc-model 0.8.1:
  изменение `kind` в неизвестных полях границ больше не считается отключением
  линии. Настоящее подавление стороны сохраняет диагностику потери.
  Публичный контракт и JSON совместимы, лицензия MIT и остальные зависимости сохранены.
- HTML/EPUB проецируют общие внешние границы таблиц и внутренние разделители
  в CSS, учитывая логические столбцы при объединённых ячейках и прямые правки
  ячеек. Это ограниченный визуальный профиль: диагонали, отступы и сложные штрихи
  диагностируются, полный перенос native declarations и обратный импорт CSS
  не заявляются. Превышение ограничений отказывает без замены предыдущего файла.

## 0.21.0 — улучшения относительно 0.20.0

- Общая модель обновлена до официального opendoc-model 0.8.0 с Border/BorderSet.
  SHA-256 wheel проверен; MIT LICENSE не изменился, остальные зависимости прежние.
- DOCX переносит прямые внешние/внутренние границы таблиц и внешние/диагональные
  границы ячеек, none/nil, стиль, RGB, толщину и отступ. Правки/удаление общих
  деклараций не возвращают исходные атрибуты; inherited style остаётся отдельным.
- Два DOCX/JSON цикла проверены по исходным атрибутам. Word 16.0.17932 подтверждает
  шесть single borders, нативную правку double/red и следующий публичный цикл.
  Визуальные правила Word для толщины двойных линий не вычисляются моделью.
- Theme/неподдержанные native детали сохраняются с расположенным LOSS. Значения,
  которые нельзя точно записать, вызывают атомарный отказ. Межформатные writers
  явно диагностируют отсутствие переноса общего оформления границ.

## 0.20.0 — улучшения относительно 0.19.2

- PDF сохраняет стек прямоугольной обрезки векторных Form XObjects. Два

- Старые HTML JSON мигрируют однократно. Неоднозначные IDs и header/group
  связи сохраняют текст и получают диагностику без выдуманных ассоциаций.
- Зависимости и лицензии профилей не изменены; модель — opendoc-model 0.7.2.
