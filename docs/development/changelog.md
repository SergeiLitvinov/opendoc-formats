# Улучшения версии

## 0.9.1 — улучшения относительно 0.9.0

- HTML записывает выявленные потери статического профиля в общий ledger OpenDoc:
  исходный файл, строка/колонка, ID элемента и связь с импортированным блоком
  сохраняются через JSON. Оценка остаётся явно неполной.
- При наличии предупреждений оригинальный HTML сохраняется как inert attachment
  с точными исходными байтами. Это не означает сохранение внешних ресурсов или
  поведения браузера. HTML writer сообщает о невоссозданных исходных функциях
  и не включает оригинальные scripts в результат.
- Ограничены чтение исходных байтов и число диагностических объектов.
  Новых зависимостей нет.

## 0.9.0 — улучшения относительно 0.8.2

- PDF импортирует конечный профиль links, notes/highlights и text/checkbox/choice/button
  widgets в стандартные контракты OpenDoc. Исходные actions и scripts сохраняются
  только как данные. Outline хранится в расширении; неподдержанные аннотации, формы,
  tagged structure, layers и catalog actions — как opaque исходный PDF.
- Для интерактивных/неподдержанных исходных объектов сохраняется ограниченная
  оригинальная PDF-копия; xref/page provenance, геометрия и JSON проверены.
  Writer явно сообщает о невоссозданных интерактивных и opaque объектах.
- Исправлена система координат повёрнутого PDF: модель использует неповёрнутые
  размеры, writer возвращает исходный поворот. Устранено незавершение layout
  на проверенной странице с поворотом 90°. Новых зависимостей нет.

## 0.8.2 — улучшения относительно 0.8.1

- DOCX записывает частичный отчёт о сложных объектах: комментариях, правках,
  content controls, полях, text boxes/WordArt, SmartArt/OLE и защите документа.
  `opaque` требует подтверждённого сохранения XML-фрагмента или части пакета;
  пропущенный объект отмечается `lost`. XPath, ID, исходная часть и причина
  сохраняются через JSON; внешняя OLE-связь не выдаётся за перенесённый payload.
- Исправлен регистр Office `OLEObject`: исходный run теперь удерживает XML объекта,
  его часть и связь сохраняются при DOCX → JSON → DOCX. Namespace чужого `ins`
  не засчитывается как поддержка Word revisions. Inventory обозначен как учёт,
  а не подтверждение сохранности каждого объекта.
- Новые зависимости не добавлены; полная семантика сложного DOCX остаётся задачей.

## 0.8.1 — улучшения относительно 0.8.0

- PPTX отмечает потери исходного package graph, переходов, анимации, структуры групп,
  audio/video и 3D settings, а также пропуски фигур без геометрии или изображения.
  Неподдержанный graphic object имеет состояние visual при сохранённом предпросмотре
  и lost при его отсутствии. Причина, XPath, исходная часть, shape ID и номер слайда
  сохраняются через JSON; оценка остаётся явно неполной.
- Исправлена сериализация имени ресурса предпросмотра OLE: тип PackURI преобразуется
  в обычную строку. Проверены реальное сохранение изображения и отсутствие ложного
  обещания переноса embedded payload.
- Source part names снимаются до изменения python-pptx по порядку показа слайдов:
  переставленные слайды сохраняют корректные ссылки в исходный ZIP и provenance секций.

## 0.8.0 — улучшения относительно 0.7.2

- TXT получил конечный `TextProfile`: UTF-8/UTF-16 LE/BE/CP1251, BOM и newline policy.
  Исходный профиль и provenance сохраняются через JSON; проверен byte roundtrip,
  включая смешанные переводы строк, пустой текст и конечную пустую строку.
- Изменение поведения чтения: CP1251 без BOM теперь выбирается явно через
  `ImportOptions(txt_profile=TextProfile("cp1251"))`; молчаливое угадывание удалено.
  Неоднозначный/невалидный ввод получает machine reason, а непредставимый текст
  не заменяет прежний выходной файл. Стандартная запись остаётся UTF-8/LF без BOM.
- Новых зависимостей нет; закрыта задача конечного профиля кодировок TXT.

## 0.7.2 — улучшения относительно 0.7.1

- EPUB сохраняет в отчёте OpenDoc конкретные потери: нелинейные главы,
  неподдержанные spine items, таблицы, MathML, inline SVG, изображения вне текстовых
  блоков или без ресурса, медиа, встроенные объекты, скрипты и ресурсы шрифтов/медиа.
- Диагностика содержит машинную причину, адрес части книги и XHTML ID либо строку/колонку;
  provenance и issues проверены через JSON и повторный импорт. Оценка остаётся неполной.
- Дополнительные зависимости не добавлены; native EPUB продолжает работать без EbookLib/lxml.

## 0.7.1 — улучшения относительно 0.7.0

- Общий результат импорта включает предупреждения EPUB, PDF и пользовательских
  читателей, а также сохранённый через JSON отчёт OpenDoc о сохранности объектов.
- Добавлены `assessment_complete` и `lossless`: успешное чтение без предупреждений
  не выдаётся за подтверждение отсутствия потерь. Состояния opaque/visual/lost/rejected
  сохраняют машинную причину, источник и различимую степень потери.

## 0.7.0 — улучшения относительно 0.6.0

- PDF-векторные ресурсы экспортируются нативными командами: линии, кривые Безье,
  прямоугольники и четырёхугольники с координатами, цветами, прозрачностью и обводкой.
- Импорт сохраняет bbox, толщину, dash pattern, caps/joins, правило заливки и замыкание.
  PDF Story больше не пытается открыть эти ресурсы как растровые изображения.
- Для неподдержанного вектора используется заданный ограниченный PNG surrogate
  с диагностикой потери и provenance; без него экспорт отклоняется атомарно.
- Проверены точное совпадение пикселей, нулевая прозрачность, JSON, неизменность
  исходной модели, предел команд, предел surrogate и отмена перед публикацией.

## 0.6.0 — улучшения относительно 0.5.0

- PDF-профили разделены по маршрутам: `pdf-rich` (PyMuPDF), `pdf-layout` (pdfplumber),
  `pdf-docx` (pdf2docx). Прежний `pdf` сохранён для совместимости.
- Чтение модели PDF, геометрия, рендер и экспорт доступны без установки OpenCV,
  NumPy, python-docx, pdfplumber и pypdf через `pdf-rich`.
- Каждый профиль проверяется после установки wheel в отдельное окружение;
  лицензии и состав зависимостей каждого профиля приведены в документации.

## 0.5.0 — улучшения относительно 0.4.0

- Собственный EPUB-контейнер читает OPF, spine, EPUB 3 nav и EPUB 2 NCX без EbookLib
  и lxml, сохраняя существующий XHTML/CSS reader. `epub` устанавливает только BeautifulSoup
  и его зависимости. Прежний backend сохранён в `epub-ebooklib` и выбирается явно.
- Проверены совпадение семантики backend, метаданные, ссылки, изображения, стили,
  JSON roundtrip, запрет внешних/escaping ссылок и XML-сущностей.

## 0.4.0 — улучшения относительно 0.3.0

- Обязательная модель обновлена до официального `opendoc-model` 0.3.0;
  импорты используют `opendoc_model`, включая примеры, тесты и изолированную установку CI.
- Проверка и очистка исходного MathML при HTML-экспорте выполняются стандартной
  библиотекой Python без lxml. DTD, объявления сущностей и чужие элементы отклоняются;
  обработчики событий и активные ссылки удаляются. Преобразование OMML остаётся
  отдельным маршрутом с собственными требованиями к движку.

## 0.3.0 — улучшения относительно 0.2.0

- Нативный DOCX: неизменяемые снимки частей, абзацев, runs и таблиц; транзакционные
  правки по исходным ID и диапазонам, вставка абзацев и spanning rows, сохранение стилей.
- PDF-контекст: текст и геометрия страниц, ограниченный PNG-рендер и кэш,
  фактический масштаб для координат OCR, различимые ошибки и закрытие ресурсов.
- Офис → PDF через отдельный профиль LibreOffice, таймаут и отмену дерева процессов,
  проверку результата и атомарную публикацию. OCR и политика приложения остаются у потребителя.
- Сборка стандартных DOCX-ресурсов в официальной модели OpenDoc без схемы приложения.
- Extra `pdf-text` для минимального текстового маршрута; ленивость новых движков.
- Исправлены нулевая прозрачность заливки/обводки PDF и настройки очень маленьких страниц.
- Расширены типизация, корпус реальных документов, изолированная приёмка пакета и CI.
- Запросы OF01–OF05 закреплены у библиотеки: подтверждённый пробел PDF-векторного экспорта
  описан конечной задачей; непроверенные направления отделены в исследования.

OpenDoc Model остаётся единственной обязательной зависимостью. Новые API не раскрывают
объекты движков или XML. Полная поддержка спецификаций форматов не заявляется.
