# Улучшения версии

## 0.7.1 — улучшения относительно 0.7.0

- Общий результат импорта включает предупреждения EPUB, PDF и пользовательских
  читателей, а также сохранённый через JSON отчёт OpenDoc о сохранности объектов.
- Добавлены `assessment_complete` и `lossless`: успешное чтение без предупреждений
  не выдаётся за подтверждение отсутствия потерь. Состояния opaque/visual/lost/rejected
  сохраняют машинную причину, источник и различимую степень потери.

## 0.7.0 — улучшения относительно 0.6.0

- PDF-векторные ресурсы экспортируются нативными командами: линии, кривые Безье,
  прямоугольники и четырёхугольники с координатами, цветами, прозрачностью и обводкой.
- Импорт сохраняет bbox, толщину, dash pattern, caps/joins, правило заливки и замыкание.
  PDF Story больше не пытается открыть эти ресурсы как растровые изображения.
- Для неподдержанного вектора используется заданный ограниченный PNG surrogate
  с диагностикой потери и provenance; без него экспорт отклоняется атомарно.
- Проверены точное совпадение пикселей, нулевая прозрачность, JSON, неизменность
  исходной модели, предел команд, предел surrogate и отмена перед публикацией.

## 0.6.0 — улучшения относительно 0.5.0

- PDF-профили разделены по маршрутам: `pdf-rich` (PyMuPDF), `pdf-layout` (pdfplumber),
  `pdf-docx` (pdf2docx). Прежний `pdf` сохранён для совместимости.
- Чтение модели PDF, геометрия, рендер и экспорт доступны без установки OpenCV,
  NumPy, python-docx, pdfplumber и pypdf через `pdf-rich`.
- Каждый профиль проверяется после установки wheel в отдельное окружение;
  лицензии и состав зависимостей каждого профиля приведены в документации.

## 0.5.0 — улучшения относительно 0.4.0

- Собственный EPUB-контейнер читает OPF, spine, EPUB 3 nav и EPUB 2 NCX без EbookLib
  и lxml, сохраняя существующий XHTML/CSS reader. `epub` устанавливает только BeautifulSoup
  и его зависимости. Прежний backend сохранён в `epub-ebooklib` и выбирается явно.
- Проверены совпадение семантики backend, метаданные, ссылки, изображения, стили,
  JSON roundtrip, запрет внешних/escaping ссылок и XML-сущностей.

## 0.4.0 — улучшения относительно 0.3.0

- Обязательная модель обновлена до официального `opendoc-model` 0.3.0;
  импорты используют `opendoc_model`, включая примеры, тесты и изолированную установку CI.
- Проверка и очистка исходного MathML при HTML-экспорте выполняются стандартной
  библиотекой Python без lxml. DTD, объявления сущностей и чужие элементы отклоняются;
  обработчики событий и активные ссылки удаляются. Преобразование OMML остаётся
  отдельным маршрутом с собственными требованиями к движку.

## 0.3.0 — улучшения относительно 0.2.0

- Нативный DOCX: неизменяемые снимки частей, абзацев, runs и таблиц; транзакционные
  правки по исходным ID и диапазонам, вставка абзацев и spanning rows, сохранение стилей.
- PDF-контекст: текст и геометрия страниц, ограниченный PNG-рендер и кэш,
  фактический масштаб для координат OCR, различимые ошибки и закрытие ресурсов.
- Офис → PDF через отдельный профиль LibreOffice, таймаут и отмену дерева процессов,
  проверку результата и атомарную публикацию. OCR и политика приложения остаются у потребителя.
- Сборка стандартных DOCX-ресурсов в официальной модели OpenDoc без схемы приложения.
- Extra `pdf-text` для минимального текстового маршрута; ленивость новых движков.
- Исправлены нулевая прозрачность заливки/обводки PDF и настройки очень маленьких страниц.
- Расширены типизация, корпус реальных документов, изолированная приёмка пакета и CI.
- Запросы OF01–OF05 закреплены у библиотеки: подтверждённый пробел PDF-векторного экспорта
  описан конечной задачей; непроверенные направления отделены в исследования.

OpenDoc Model остаётся единственной обязательной зависимостью. Новые API не раскрывают
объекты движков или XML. Полная поддержка спецификаций форматов не заявляется.
