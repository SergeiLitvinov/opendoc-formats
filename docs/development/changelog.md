# Улучшения версии

## Накопленные улучшения относительно 0.42.0

- PDF-layout учитывает измеренные пропорции колонок DOCX и не схлопывает
  вложенную таблицу вокруг изображения. Проверяются контейнер и область страницы;
  переполнение без текста тоже отклоняется атомарно. Приняты обычные/merged/nested
  ячейки, crop/rotation и исходные RGBA pixels; native Word row splitting
  и точная source pagination остаются явно отмеченной потерей flow-профиля.
- Однострочный PDF→DOCX flow сохраняет явный snapshot исходной сетки и привязку
  к таблице. После нормализации Word 3→2 столбца импорт восстанавливает исходный
  grid/span без догадок по тексту. При структурной правке или повреждении metadata
  остаётся фактическая сетка Word с диагностикой. Проверены нативная замена текста,
  два JSON/DOCX-цикла после неё и отсутствие дубликатов OPC-частей.
- PDF → Model → DOCX flow сохраняет разные цвета/толщины границ отдельных ячеек,
  включая горизонтальные/вертикальные объединения и crops. План сверяется с
  фактическими `tcBorders`, `gridSpan` и `vMerge` до публикации. Два JSON/DOCX-цикла,
  открытие и правка в Word подтверждены; внутри merged cells нет лишних линий.
- GSUB contextual types 5/6 format 2 и ClassDef formats 1/2 читаются собственным
  кодом без fontTools в принятом профиле. Проверяются диапазоны глифов, class 0,
  правила, offsets и ссылки; class labels не подменяются glyph IDs.
  Сохранены Unicode policy, PDF shaping, лимит работы и отмена.
- GSUB contextual types 5/6 format 1 читаются собственным кодом, включая NULL
  RuleSet, общие наборы и повторные ссылки на правила. Проверяются IDs глифов,
  offsets и вложенные lookup references без их выполнения; Unicode policy
  сохраняется. Повторный обход расходует бюджет, отмена не вызывает fontTools.
- GSUB contextual types 5/6 format 3 и 7→5/6 проверяются собственным reader:
  coverage, границы и ссылки на вложенные lookups не требуют fontTools
  в принятом профиле. Вложенные операции не выполняются, Unicode policy сохраняется;
  formats 1/2 и sequenceIndex после расширения input sequence сохраняют fallback.
- Соседние GSUB ReverseChainSingleSubst type 8/7→8 больше не включают fontTools
  в принятом статическом TrueType-профиле. Собственный reader проверяет coverage,
  контексты, offsets и выходные glyph IDs, сохраняя Unicode policy и PDF shaping.
  Проверены повреждения, лимит работы, отмена и неизменность пикселей PDF.
- Повторное subsetting идентичных программ и символов использует ограниченный
  LRU, сохраняя байтовый результат и license/copyright records. Проверены смена
  bytes/настроек, права no-subsetting, вытеснение, параллельный доступ и отмена;
  первичное построение шрифта остаётся у fontTools.
- Добавлен собственный структурный аудит sfnt: порядок tags, search fields,
  padding и пересечения таблиц с исходными offsets. Доступен через прямой API,
  `sfnt_structure=True` и CLI `--sfnt-structure`, включая выбранный TTC face;
  findings расходуют общий бюджет Anatomy. Исправление исходников не выполняется.
- Anatomy и CLI поддерживают явно выбранный TTC face: `sfnt_face_index` /
  `--sfnt-face-index`. Исходная коллекция сохраняется целиком, locators включают
  номер face, все payload и абсолютные offsets доступны без fontTools.
  Проверены общие квоты, отмена, сравнение и отказ от standalone checksum-аудита TTC.
- Явно выбранные faces TTC 1.0/2.0 читаются собственным sfnt-инспектором по
  исходным абсолютным адресам; shared tables сохраняют payload. Метаданные face 0
  в resolver не требуют fontTools для принятого профиля. Проверены TrueType/CFF,
  системные коллекции и установленный base wheel; embedding TTC не заявлен.
- Покрытие символов из выбранной Unicode `cmap` 2 читается собственным кодом:
  single-/double-byte ranges, общие массивы, нулевые IDs и delta modulo 65536
  совпадают с прежним reader. Сохранены Unicode priority, квоты, отмена и fallback;
  legacy-кодировки не превращаются в Unicode. Минимальный base wheel не требует
  fontTools для этого профиля.
- Поддержанные SingleSubst рядом с ligature lookups больше не требуют fontTools
  для чтения GSUB/ToUnicode. Собственный reader проверяет оба формата, coverage,
  extension wrappers, размеры и glyph IDs; прежняя политика Unicode и PDF shaping
  сохраняется. Проверен установленный минимальный PDF-профиль с собственным шрифтом.
- Опциональный PDF TextLayout связывает точные glyph observations с диапазонами
  текста через публичный Model API: `fi` сохраняет связь 2:1 и snapshot версии 2.
  Изменённые текст/стиль дают stale; повторный захват не подтверждает прежнюю
  геометрию, сохраняет сторонние layouts/extra и атомарность отмены.
  Полный paint state, reading order и native writer projection остаются открытыми.
- Собственный GSUB/ToUnicode reader поддерживает статический TrueType с `post` 1.0
  в дополнение к 2/3: этот профиль обходится без fontTools. Проверены совпадение
  mappings с прежним reader, восстановление текста и неизменность пикселей PDF;
  остальные ограничения shaping и настоящий subsetting сохраняются.
- Закреплён официальный OpenDoc Model 0.19.0 с контрактами C-TEXT-LAYOUT-01/02:
  типизированные глифы, кластеры и атомарные пакетные операции доступны в обычной
  среде адаптера. MIT не изменён, остальные закреплённые зависимости прежние.
  Расширение конечного PDF reader профиля и проекция в writer остаются C-PDF-01.
- `PdfDocument.page_text_placements` сохраняет точные native glyph matrices,
  форму глифа, Unicode/ID continuations и отдельные fill/stroke/ignore/clip
  occurrences. Учтены Form/CTM, font program digests, квоты и отмена. Заимствованные
  native wrappers освобождаются до восстановления страницы; отказ не оставляет
  частичный снимок или изменённый Rotate. Общая Model-проекция и writer остаются
  C-PDF-01; новые движки не нужны.
- Бинарный инспектор читает CFBF v3/v4: физические секторы, FAT/DIFAT/miniFAT,
  directory objects и обычные/малые потоки с исходными диапазонами и SHA-256.
  Неиспользуемые bytes сохраняются; циклы/пересечения/неверные размеры дают отказ.
  Поддержано чтение старого v3 с неинициализированным high DWORD размера.
  Независимый Windows IStorage подтвердил байты собственных оригиналов без
  активации OLE. Storage tree и семантика вложенных форматов не объявляются
  принятыми; новых зависимостей и изменений Model нет.
- `BinarySnapshot.epub` сохраняет исходные manifest references всех выбранных
  EPUB rootfiles. Внешние адреса наблюдаются как `external-unassessed`, без доступа
  к сети/файлам и без заявления об их валидности. Неизменяемый инвентарь сохраняет
  атрибуты и source locations, поддерживает JSON и буквальное сравнение. Квоты,
  отмена и строгий reader сохранены; новых зависимостей и изменений Model нет.
- Общий codec OpenDoc Model проверяет JSON до
  копирования и не вызывает пользовательский `__deepcopy__` для JSON-контейнеров.
  API и схема модели прежние. Полный wheel и MIT license проверены по SHA-256;
  остальные закреплённые зависимости не изменены. Парсинг и политика переноса
  форматов остаются в Formats.
- Привязка PDF-текста к операциям рисования использует неизменяемые нативные
  наблюдения глифов. Неизвестный Unicode и неоднозначные совпадения дают явную
  причину неопределённости; повторный анализ удаляет устаревшие paint-признаки.
  Выбранные лимиты импорта и отмена действуют внутри сопоставления. Новых
  зависимостей и изменений общей модели нет; полная проекция глифов ещё не принята.
- Добавлен ограниченный `PdfDocument.page_text_spans`: неизменяемые glyph positions,
  Unicode/glyph ids, native paint state и metadata без дополнительных обработчиков.
  Span/glyph/metadata budgets и отмена не возвращают частичный снимок; неизвестный
  Unicode не восстанавливается эвристикой. Оба текстовых API сохраняют исходный
  Rotate и его наследование после успеха/ошибки backend. Полный C-PDF-01 остаётся открытым.
- Инспектор EPUB определяет XML по OPF media types, включая extensionless UTF-16
  ресурсы и несколько rootfiles с общими ресурсами. Управляющие части и ресурсы
  читаются/учитываются один раз в общем бюджете; binary остаётся opaque.
  XML policy, отмена и явные отказы действуют до дальнейшего чтения.
  Локальный href resolver общий с reader; дополнительные пакеты не требуются.
- `BinarySnapshot.opc` описывает физические связи пакета, владельцев, цели,
  пробелы и достижимость частей, включая несвязанные циклы. Повреждённый граф
  не объявляет все недостигнутые части доказанно недостижимыми. Payload остаётся
  исходным, а строгий импорт не смягчается. Исправлен Content Type `_rels/.rels`;
  resolver общий с DOCX, новых зависимостей и изменений Model нет.
- Общий бинарный инспектор определяет XML по OPC Content Types, включая части
  без расширения; declared binary сохраняется opaque. Manifest учитывается один
  раз в общем бюджете, DTD/квоты/отмена действуют и для найденных таким образом
  XML-частей. Разбор деклараций общий с переносом DOCX-компонентов и не требует
  Office/XML backend; состав зависимостей не меняется.
- Добавлено препарирование ZIP/OOXML/EPUB и активных PDF-объектов: исходные части,
  wire/content hashes, XML nodes/attributes, неизвестные бинарные payload,
  encoded streams и признак ремонта PDF backend. CLI сохраняет читаемый инвентарь,
  исходные части и буквальное сравнение; общая модель и зависимости не меняются.
- DOCX сохраняет физически недостижимые OPC-компоненты и их зависимости через
  OpenDoc/JSON и обратный экспорт. Исходные payload и `.rels` остаются побайтно
  прежними; коллизии имён с редактируемыми частями разрешаются без подмены данных.
  Неверные связи, превышение бюджета и отмена сохраняют прежнее назначение.
- Нативный DOCX reader исключает tab stops из текста, сохраняет `noBreakHyphen`
  и согласованные offsets/runs; правка на границе сохраняет native no-break token.
  `CellSnapshot.text` разделяет исходные абзацы переводами строк, включая пустые,
  без разворачивания merged cells. Контракт приёмки — C-DOCX-NATIVE-TEXT-01.
- Model → Text сообщает известные потери оформления, ссылок, ресурсов, формул,
  геометрии и прочей структуры с исходными адресами. Текст вложенных таблиц и
  объектов остаётся в ячейке. Позиционные таблицы восстанавливаются в порядке
  блоков без дублирования; неоднозначные ссылки отвергаются.
- Проверки используют независимые DOCX/PDF bytes, а не оригинал от нашего writer.
  Подготовлены проверки нативной правки в Word и Poppler-сравнения отображения.
- Адаптеры поддерживают отмену и выбранный бюджет Model; HTML wrapper передаёт
  их обеим стадиям. Безопасный ZIP-разбор доступен для in-memory источника;
  архивная квота отличается от повреждения контейнера.

## 0.42.0 — улучшения относительно 0.41.0

- Официальный Model 0.18.0 предоставляет общий codec `IntegrationModel`.
  `Text.diagnostics` и переходы Text → OpenDoc → JSON сохраняют исходные
  отрицательные оценки, reason, location, provenance и record extra.
  Повторяющиеся сообщения разных объектов остаются отдельными записями;
  положительные claims исходного богатого документа не переносятся в текстовый view.
- PDF/OCR сохраняют адресную диагностику сбоев анализа таблиц, изображений,
  векторов и расположения ячеек; отсутствие байтов изображения имеет `lost`,
  непроверенный результат анализа — `opaque`. Публичный отчёт не дублирует явно
  связанные legacy warnings и сохраняет записи через JSON.
- Текстовые PDF backend/page failures и OCR failures имеют явные типы.
  Отмена и превышение лимитов прекращают fallback; табличный результат без
  plain text больше не отбрасывается. Проверки отмены проходят между движками,
  страницами и семантическими блоками. Очистка NUL/замещающих символов pypdf
  сопровождается оценкой неопределённости декодирования.
- Отсутствующий backend HTML/EPUB и отказ, timeout либо пустой hidden text DjVu
  имеют source-only диагностику. Полный инвентарь объектов, отброшенных при
  упрощении в текст, остаётся открытой задачей; `assessment_complete` не повышается.
- Новых зависимостей нет. Лицензионный реестр привязан к проверенному wheel
  Model 0.18.0 (MIT); остальные закреплённые зависимости не изменены.

## 0.41.0 — улучшения относительно 0.40.0

- Добавлен публичный `DocxProfile(layout="flow")` для канонической PDF-модели:
  выбранные строки/столбцы и порядок блоков экспортируются в редактируемый DOCX
  без позиционного моста. Конечный профиль исходной сетки заменяет линии
  проверенными нативными границами, учитывает occurrences и исключённые участки.
  Потеря исходных координат/пагинации имеет явную LOSS; неоднозначная графика,
  неизвестный paint-state и дополнительные потери содержимого отклоняются.
- Diagnostics flow сохраняют адреса канонической модели, включая шрифтовые
  подстановки после исключения сетки. Проверены два DOCX/JSON цикла, правка
  таблицы в Microsoft Word, пределы, отмена и атомарный отказ quality gate.
- Отмена DOCX/PPTX проверяется внутри построения сетки, продолжений merges,
  наследования заголовков, векторных сцен и сбора групп/серий диаграмм.

- DOCX с сохранённым opaque OOXML встраивает выбранные разрешённые font programs
  целиком. Subsetting по одним семантическим runs больше не удаляет глифы текста
  smartTag при двух DOCX/JSON циклах. FONT references и исходный XML сохраняются;
  известная LOSS неподдержанной семантики smartTag не скрывается.
- `font_embedding.subset_policy` показывает полную программу либо semantic usage.
  Обычные документы сохраняют прежний subsetting. Размер DOCX с opaque содержимым
  может увеличиться; уже отсутствующие во входной программе глифы не восстанавливаются.
- C-FONT-OPAQUE-01 фиксирует оставшиеся opaque-only faces/variants, каскад и
  пакетные примечания. Model 0.17.0, общий codec и состав зависимостей не меняются.

## 0.40.0 — улучшения относительно 0.39.1

- Обязательная зависимость обновлена до официального `opendoc-model==0.17.0`;
  используется namespace `opendoc_model`. Типы, JSON и валидация принадлежат Model,
  форматные парсеры, layout и политики преобразования остаются в Formats.
- Конечный текстовый TeX-профиль записывается без DOCX/lxml: заголовки, структурные
  списки с продолжениями/родителями/счётчиками, формулы и текстовые индексы.
  Семантические правки и удаление роли не восстанавливаются из нативных hints.
  Независимые оригиналы и два JSON/TeX цикла проверяются компилятором и по pixels.
  Объекты вне принятого профиля имеют явную диагностику или отказ.
- PDF сохраняет диагностику отдельных OCR results через rich import и JSON.
  Переполнение inline изображения в body-абзаце вызывает ограниченный перенос,
  сохраняя размеры, crop/rotation, подписи и последующий текст. Проверка текста
  блокирует публикацию при пропусках; таблицы и сложные смешанные абзацы имеют
  отдельные ограничения.
- Нативный импорт PDF, DOCX, PPTX, HTML/EPUB и TXT и экспорт DOCX/PPTX,
  HTML/EPUB/TeX/TXT проверяют отмену внутри собственного обхода. Отмена перед
  атомарной публикацией сохраняет прежнее назначение; runtime callback не хранится
  в Model. Отдельные вызовы движков и кодеков остаются непрерываемыми.
- Экспериментальный PDF → Model → DOCX использует явные ссылки на font resources
  и конечные graphics scopes: обрезку, Form XObject и редактируемые Word-группы.
  Самостоятельная подготовка проверяет отмену. Это не полная замена pdf2docx:
  общая композиция прозрачности, сложные masks/blend и частично обрезанный текст
  остаются за quality gate и в TODO. Прежний backend доступен через `pdf-docx`.
- Удалена неиспользуемая build-зависимость. Нативный текстовый TeX уменьшает
  необходимый runtime-состав. PDF-профили ограничивают PyMuPDF веткой `<2`,
  исключая неиспользуемый обязательный ML/layout стек major 2; проверенный
  минимальный PDF-профиль содержит Formats, Model и PyMuPDF 1.28.2.
  Сторонние версии lockfile и их лицензионные доказательства сохранены.
- Реализованные профили и приёмка описаны в руководстве и корпусе; TODO содержит
  оставшуюся работу. Полнота произвольных исходных форматов не объявляется.

## 0.39.1 — улучшения относительно 0.38.0

- DOCX хранит прямые before/after spacing и четыре флага переноса отдельно от
  наследования. Правка/удаление стиля, абзаца и defaults обновляют нативные
  объявления; прямые 0/false сохраняются. Другие оси spacing и line rule не теряются.
- Неизвестные units/auto-spacing/flags и неподдержанные владельцы диагностируются;
  непредставимое значение отказывает до публикации. Межформатные потери явно
  отмечены, HTML/EPUB/PPTX получают отдельный view известных интервалов.
- Оригинал, два DOCX/JSON цикла, независимые native references, правки и сброс Word
  проверены по полным страницам при 96 dpi. Остальные части C-DOCX-05 остаются в TODO.
- Новых зависимостей нет; Model 0.13.0 и версии всех сторонних пакетов не меняются.

## 0.38.0 — улучшения относительно 0.37.0

- Удалены дублирующий EPUB backend EbookLib и extra `epub-ebooklib`; ни один
  профиль больше не устанавливает этот AGPL-пакет. Собственный контейнер сохраняет
  OPF, spine, nav/NCX, метаданные и исходные XML; XHTML читает BeautifulSoup.
- Независимые ZIP/XHTML fixtures проверяют ссылки, CSS, изображения, таблицы,
  MathML, nonlinear главы и JSON roundtrip без EbookLib. Устаревший выбор backend
  отклоняется с инструкцией перейти на `native`; используйте extra `epub`.
