## Конечные контракты

Приоритет реализации: C-PDF-01 и C-MAP-01, затем C-DOCX-01/02.
Это собственные синтетические примеры; пользовательские документы не входят
в библиотечные fixtures. План реализации находится в [TODO](todo.md).

### C-FONT-OPAQUE-01

Владелец — Formats. Сохранённый native OOXML не должен приводить к удалению
нужных ему глифов при встраивании шрифта. Когда target package содержит retained
opaque roots, выбранные и разрешённые к embedding программы сохраняются целиком.
Это конечная защитная политика, а не семантическая интерпретация smartTag/fields.
Существующая located LOSS для неподдержанной семантики остаётся; поднимать бюджет
потерь, удалять FONT references или подменять явно связанный ресурс системным
шрифтом ради прохождения приёмки нельзя.

Собственный smartTag с текстом `OwnSmartToken` проверяется в двух публичных
DOCX → Model → JSON → DOCX циклах: XML и glyph coverage сохраняются, исходник
не меняется, FONT references остаются и дополнительного `font-glyphs` LOSS нет.
Открытая часть: opaque-only families/variants, пакетные footnotes/endnotes и
полный условный каскад. Для них нужно доказать inventory/embedding и визуальную
приёмку по оригиналу; наличие полного выбранного font face этого не доказывает.
Model хранит существующие FONT resources/references и JSON. Новых типов или
изменений общего codec этот контракт не требует.

### C-PDF-DOCX-01: собственный маршрут и граница библиотек

PDF → публичная модель OpenDoc → DOCX принадлежит OpenDoc Formats. Здесь остаются
разбор PDF, определение колонок/таблиц, чтение встроенных шрифтов, измерение
исходных базовых линий и порядка рисования, разрешение шрифтов, подготовка
частного представления и запись нативного OOXML. Модель не должна импортировать
PyMuPDF, python-docx, fontTools или содержать правила компоновки Word.

Используются существующие публичные `Box`, `Paragraph`, `TextRun`, `Table`,
`ResourceKind.FONT`, provenance, ширины таблиц, обход, лимиты и JSON codec Model.
Исходные сведения `pdf_*` и нативные свойства `docx_*` описывают форматы и
обрабатываются только адаптером. Частное представление не меняет исходный документ.
Одинаковые общие данные не получают второй codec или параллельные общие типы.

Расширение Model запрашивается только для воспроизводимого пробела её публичного
API. Явный запрос содержит минимальный документ, отсутствующую общую семантику,
предлагаемый интерфейс и значения unknown, JSON roundtrip, ограничения,
совместимость и критерии приёмки. Запрос передаётся агенту OpenDoc; наличие
запроса не считается его реализацией. Для текущего конечного текстового профиля
расширение Model не требуется.

Приёмка замены pdf2docx: независимые исходные PDF с колонками, таблицами с/без
границ, объединениями и многострочными ячейками, растровыми рисунками/сканами,
векторами, встроенными шрифтами и формульными глифами. Сравниваются страницы,
видимый текст, координаты и порядок наложений в Word относительно оригинала,
затем два DOCX/JSON цикла и нативная правка. Сохранение формульных глифов не
объявляется восстановлением математического AST. Ошибка, неизвестная геометрия,
лимит, отмена, отказ quality gate и изменение PDF сохраняют прежнее назначение.
Набор простых совпадающих страниц не закрывает приёмку произвольных PDF.

### C-PDF-01

Нативные URI links, notes, highlights и text widgets сохраняются относительно
оригинала в двух PDF → JSON → PDF циклах на обычных/240×200 pt страницах и
поворотах 0/90/180/270. Проверяются geometries, значения, canonical field tree
и widgets, явные правки/удаление и выбранная native правка с последующим циклом.
Actions не исполняются; неподдержанное имеет located typed diagnostics.
Ошибки, лимиты, отмена и превышение бюджета сохраняют предыдущий файл.

Public native PDF inspection возвращает подтверждённый сопоставимый text flow
в объявленном профиле; неизвестное не равно нулю. Текст научного DOCX проверяется
в PDF относительно источника, с адресным отказом при настоящей потере.
Совпадение text flow не объявляет точной компоновку. Нативный text profile не
выдаётся за полный model object inventory, чтобы не разблокировать посторонние
object/formula gates. Общая часть этого контракта согласуется с OpenDoc Model.

### C-MAP-01

Первый профиль — существующий vector→PNG fallback. Публичная карта содержит
source handle/provenance, representation/resource и подтверждённые target
handle/resource/native locator; неподтверждённый locator остаётся unknown.
Повторные occurrences различимы. Состояния semantic/visual/opaque/lost/rejected,
reason/code, версия/формат/полнота и статус публикации представлены машинно.
Растр не считается редактируемым вектором; сообщение не служит схемой данных.

Связи проходят два JSON/форматных цикла, перестановку, удаление и перенумерацию
без dangling references. Правила split/merge объявлены явно. Отказавшая попытка
не считается опубликованным результатом; лимиты, отмена и rollback проверяются.
Общие типы и JSON принадлежат Model, вычисление и native подтверждение — Formats.

### C-DOCX-01/02

Прямой `tblInd=600 dxa` сохраняет 30 pt в Word через два цикла; tab stop 396 pt
с right alignment и line leader сохраняет свою позицию, выравнивание и заполнитель.
Поддержаны явные правки, удаление без возврата legacy значений, JSON и ограничения.
Утрата имеет адресную диагностику, чтобы нулевой бюджет мог отказать атомарно.
Общий font warning не описывает потерю отступа/табуляции. Сначала используются
существующие величины/properties Model; парсинг и правила Word принадлежат Formats.
