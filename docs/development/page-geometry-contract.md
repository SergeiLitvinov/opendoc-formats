# C-PAGE-DEFAULTS-01: исходная и предполагаемая геометрия страницы

Статус: реализация в рабочей копии OpenDoc Model прошла изолированную
[consumer-проверку](page-model-consumer-evidence.json). Production использует
опубликованный `opendoc-model==0.19.0`, который нового API не содержит;
производственное подключение и приёмка writers остаются открытыми.

Кандидат собран из 53 неизменённых исходников с SHA256
`f885ff8395d6e5a085cbb8bd52190c9d02ddeb796059fa35ec21b8d067750792`.
Его metadata version также 0.19.0, поэтому identity задают source/wheel SHA,
а не номер опубликованного выпуска. Проверялись отдельные установленные wheels;
основная среда и исходники Model не менялись.

Публичный кандидат предоставляет `PageSettingValue`, `PageSettingsState`,
`get/set_page_settings_state`, `accept_page_settings`, `invalidate_page_settings`.
Десять независимых consumer-групп покрывают partial/zero/unknown/computed/source/explicit,
два официальных JSON-цикла, same-number acceptance, detached stale после прямой
правки, атомарность batch/serialization refusal, удаление оценки, opaque/future
versions, unknown fields и budgets getter/setter/accept/invalidate/codec.
Прототип Formats сопоставляет 15 независимых XML/ZIP исходников с source/unknown,
а измерения Word — с computed и явным basis. Raw omissions не меняются;
этот prototype не доказывает материализацию принятия того же числа в DOCX
или подключение нового общего состояния в production reader/writers.

## Проблема

`PageSettings` требует числовые width/height и четыре margin Length. Исходный
формат может не объявлять часть или все эти поля. Число, выбранное адаптером
для построения допустимой Model, не доказывает геометрию исходного документа.
Само присваивание того же числа также не выражает, что пользователь принял
предположение как явную настройку.

Независимые XML/ZIP DOCX в Word 16.0.17932 показывают различие отсутствующего
`pgSz` при существующем `sectPr` и отсутствия самого `sectPr`: 612×792 pt
против A4 из среды. Отсутствующие margins берутся из среды; перенос такого
значения в общие данные без происхождения создал бы ложную определённость.
Это наблюдение конечного корпуса, а не нормативный default всех приложений.

## Требования к общему API

- Необязательное, нейтральное к форматам представление исходной определённости
  шести полей `PageSettings`: явно известно, не объявлено/неизвестно, вычислено
  с указанным основанием. Известный нулевой margin отличать от отсутствующего.
- Не заменять отсутствие числом из default factory. Сохранить совместимость
  существующего `PageSettings` и обычных документов, созданных пользователем:
  неизвестность источника должна задаваться явно, без переоценки всех legacy Model.
- Явный способ принять/переопределить geometry, включая случай, когда новое число
  равно прежнему placeholder. Мутации и helpers не должны молча объявлять
  устаревшую оценку актуальной. Renderer должен различать unresolved source
  и явную пользовательскую настройку.
- Официальный JSON codec, валидация единиц/конечности/состояний, budgets, unknown
  version policy и документированная миграция. Не вводить собственный codec в Formats.
- Выбор конкретных DTO/helpers согласовать с существующим API Model; обязательна
  различимость состояний и правок, а не предложенные здесь имена классов.

## Разделение ответственности

Model хранит общую геометрию, происхождение оценки и её актуальность.
Formats разбирает `pgSz`/`pgMar`/`sectPr`, сохраняет native XML/omissions и связи,
выбирает документированный projection policy, измеряет Word/PDF и диагностирует
неподтверждённый перенос. Word/OOXML, принтеры, системные шаблоны и COM не входят
в Model. Model не выбирает Letter/A4 или margins среды по расширению файла.

До общего API Formats использует собственную привязку `opendoc_formats.docx_page`:
native declarations и признаки пропусков переживают JSON/DOCX; неопределённые
числовые проекции диагностируются, их перенос в другие layout-форматы получает LOSS.
Это не реализация общего контракта.

## Приёмка

- API и официальный JSON сохраняют independent partial/unknown/explicit geometry,
  Length и zero margins; выполняется два цикла без изменения входного объекта.
- Явная правка, принятие того же placeholder и удаление/устаревание оценки
  имеют различимый результат; старые Model без нового расширения работают прежним образом.
- Отказы для неверных значений, несовместимых состояний, неизвестной версии и
  превышения budgets имеют явные адреса и не меняют назначение.
- Model не импортирует Formats и движки. После выпуска Formats отдельно проверяет
  wheel, исходные DOCX, native omission replay, нативную правку и межформатную диагностику.
