# C-TEXT-LAYOUT-01/02: позиции глифов, семантический текст и пакетная запись

Статус: контракты доступны в закреплённом официальном Model 0.19.0;
конечная потребительская приёмка release wheel пройдена.
Подключение к рабочим PDF reader/writer Formats остаётся отдельной задачей.
Зависимая задача — C-PDF-01 в [TODO](todo.md).

## Потребительская проверка

Проверен официальный Model `0.19.0`, SHA-256
`0ec3aa5c409d9ae05aa4e979d7a15e81b251318ca782a5b0395039f80c3232fd`.
MIT LICENSE прежний. Код совпадает с принятым consumer5 после нормализации
переводов строк и исключения номера версии; форматные движки в Model не добавлены.
Этот release wheel закреплён в основной зависимости Formats и `uv.lock`.
Одиннадцать проверок Model API и 21 проверка защиты экспорта проходят в обычной
среде с официальным пакетом: 32 passed. Проверки API больше не пропускаются
из-за отсутствия экспериментального модуля.
Артефакты, hashes и конечная область проверки записаны в
[машинном свидетельстве](text-layout-consumer-evidence.json).

Одиннадцать проверок используют `PdfDocument.page_text_placements` и самостоятельные
PDF originals с собственным single-face TTF, ToUnicode и ActualText. Подтверждены
точные матрицы/FONT после двух JSON-циклов, `fi` 2:1, ActualText 1:N, сохранение
отдельных fill/stroke, unknown mappings, атомарный missing FONT отказ и 12 000
физических glyph rows с выбранным бюджетом. State verified подтверждает заявленную
связь, а не полный native rendering/visibility или покрытие всех объектов PDF.

После прямой правки одного текста все связанные snapshots устаревают. Для набора
есть публичный `invalidate_text_layouts(document, ("fill", "stroke"))`; одиночный
вызов не является заменой этой транзакции. Неполный/неверный набор не меняет
документ, общий validation остаётся включённым, unknown не повышается. Режим без
ID явно выбирает все вхождения. Глифы, диапазоны, provenance и unknown fields
сохраняются. Formats использует только публичный Model API и не копирует codec.

## C-TEXT-LAYOUT-02: пакетная запись и размер привязки

Для страницы с множеством paint occurrences нужен публичный
`set_text_layouts(document, layouts, *, verify=False, limits=None)`:
объединение по ID сохраняет остальные layouts, extra и общие реестры.
Нормализация входа, общий контекст snapshot и финальная валидация должны работать
пакетно. Дубли ID, неверная ссылка или превышение выбранного бюджета не оставляют
частичной записи. Одиночный setter не заменяет пакетную операцию при импорте страницы.

Точные кластерные диапазоны сохраняются: один длинный TextRun не должен повторяться
целиком в snapshot для каждого диапазона. Нужны общие владельцы текста без потери
offsets, affinity, порядка связей и stale-проверки. Formats не укрупняет диапазоны
ради обхода квот и не использует внутренний fingerprint Model.

В принятом dev API новые явные подтверждения имеют `binding_version=2`.
Документ без этого поля использует версию 1 и сохраняет прежний fingerprint;
только явное `verify=True` обновляет привязку до версии 2. Проверены два JSON-цикла
исходного snapshot от SHA-проверенного установленного consumer2 и его явное обновление.
Это проверка совместимости представления, а не повторная сертификация PDF-рендера.

Потребительская приёмка включает 16 реальных PDF-вхождений и 1 245 кластеров,
в том числе 1 200 точных диапазонов одного длинного текста с `fi` 2:1.
Матрицы и диапазоны сохраняются через два JSON-цикла с явным `max_nodes=1000000`;
после правки одного владельца его привязка устаревает, соседняя остаётся актуальной.
Проверены атомарные отказы по дублям, ссылкам и квоте, сохранение extra и независимость
возвращаемых данных. Проверка конечного корпуса не доказывает асимптотику произвольной
страницы; счётчики внутренней работы принадлежат приёмке Model.

Основной потребительский gate:

```sh
uv run --frozen pytest tests/native/test_text_layout_consumer.py tests/test_text_layout_export.py
```

Для проверки будущих dev-wheel с доверенной контрольной суммой доступен отдельный инструмент:

```sh
uv run --frozen python -m tools.text_layout_preview --model-wheel <model-dev.whl> --sha256 <sha256>
```

Инструмент создаёт отдельные dev-артефакты, проверяет source hashes, версии и
зависимости изолированного окружения, запускает `tests/native/test_text_layout_consumer.py`
и сохраняет provenance/logs под `.opendoc-formats`. Основные версии, lock и исходники
пакетов не меняются, публикация не выполняется.

## Назначение контракта

`TextRun` хранит семантический текст и стиль, `TextRange` связывает позиции по ID
и offset, `FontReference` указывает программу шрифта. `TextLayout` дополняет их
расположенными глифами и проверяемой связью с диапазонами текста. `VectorPath`
сохраняет контуры, но не заменяет редактируемый текст. Общий codec и проверка
актуальности принадлежат Model; парсинг, shaping и paint evidence — Formats.

Formats уже получает `PdfTextSpan` / `PdfGlyphInfo` через
`PdfDocument.page_text_spans`. Прямые wire originals и отрицательные контроли —
`tests/native/test_pdf_text_spans.py` и `tests/readers/test_pdf_paint_matching.py`.
У одного текста могут быть отдельные fill/stroke occurrences; ligature continuation
содержит Unicode при glyph id `-1`. Нативный порядок не доказывает порядок чтения.
Полное отображение этих наблюдений в общую модель пока не принимается.

## Поведение Model

Нужен необязательный форматонезависимый контракт text layout, использующий
существующие ID, диапазоны, единицы/преобразования, FONT resources и provenance.
Точные имена API и место хранения выбирает Model; новая параллельная модель
текста и форматный PDF codec не требуются.

- Layout связывает один или несколько логических диапазонов с размещёнными
  глифами/кластерами. Сохраняются позиции и преобразование в явно определённой
  системе координат, принадлежность странице/сцене и порядок в layout occurrence.
  Координаты конечны; порядок glyph records не становится порядком чтения.
- Связь many-to-many: `fi` может занимать два Unicode codepoints и один glyph,
  а один символ — несколько глифов. Отдельные paint occurrences сохраняются
  раздельно; от них нельзя требовать единственной общей привязки.
- Glyph id имеет смысл только относительно явной программы шрифта и face.
  Отсутствующий glyph/font/mapping остаётся явно неизвестным. Нативный sentinel
  `-1` не превращается в валидный glyph id; raw PDF observation остаётся у Formats.
  Нельзя выводить Unicode, glyph id, coverage или шрифт из соседства/имени семейства.
- Семантическая связь различает подтверждённую, неизвестную и утратившую
  актуальность привязку. Изменение текста не оставляет прежний layout молча
  действующим. Нужен документированный механизм проверки текста-владельца и
  явного remap либо invalidation после split/merge/extract/delete/ID remap.
  Повторная раскладка и восстановление актуальности принадлежат потребителю.
- Публичный codec сохраняет данные и неизвестные поля через два JSON-цикла,
  возвращает независимые контейнеры. Проверяются ссылки на диапазоны/страницу/
  сцену, тип и наличие FONT resource, границы offsets и выбранные бюджеты.
  Неподтверждённые связи не объявляются валидными из-за совпадения ID.
- Layout отсутствует у прежних документов без изменения их поведения.
  Недопустимые ссылки, NaN/Infinity, неверные индексы и квоты дают адресные ошибки;
  отказ не изменяет документ и не оставляет частично записанный layout.

Хранение должно быть ограниченным и пригодным для больших страниц. Не следует
неявно повышать общий бюджет или обходить nodes/depth/bytes/embedded bytes.
Model выбирает компактное типизированное либо ресурсное представление; его
публичные ограничения и расход квот должны быть документированы. Formats не
создаёт собственный общий JSON codec или неконтролируемый dict на каждый glyph.

## Защита до подключения проекции

Реестр экспорта Formats отвергает запись непустого layout через обработчик без
явного `supports_text_layouts=True`: ERROR `export.text-layout` возвращается до
проверки движка, создания каталога и временного файла. Прежнее назначение и модель
сохраняются. Guard охватывает типизированный реестр нового Model и opaque extra
прежнего Model, без разбора общей схемы в Formats. JSON остаётся доступен через
публичный codec; два фактических экспорта сохраняют исходный реестр. Это защита
границы `write_document` / `ExporterRegistry.write`, а не реализация нативного writer.

## Разделение ответственности

| Model | Formats |
| --- | --- |
| Общие данные layout, диапазоны и FONT references | PDF parsing, извлечение glyph observations и font-program binding |
| Codec, независимые значения, лимиты и ссылочная валидация | Координатная проекция исходного формата и соответствие конкретного glyph семантике |
| Remap/invalidation и явная актуальность привязки | Shaping, измерения, clipping, paint seq/type/opacity, blend, layers и порядок рисования |
| Совместимость документов без layout | Writer, opaque/visual fallback, диагностика потерь и нативная приёмка |

Ни PyMuPDF, ни parser шрифта, ни layout/shaping engine не становятся обязательными
зависимостями Model. Model не определяет видимость PDF-текста, не исполняет
ресурсы и не гарантирует совпадение рендера. Formats не принимает сохранённую
геометрию за доказательство отсутствия потерь после редактирования.

## Приёмка

1. Обычный текст, `fi` 2:1, combining mark 1:N, RTL/непоследовательные позиции,
   два paint occurrences, неизвестное сопоставление и отсутствующий font binding.
   Эти случаи не обязаны быть получены из PDF: Model проверяет общие данные.
2. Два JSON-цикла, unknown fields и независимость вложенных значений;
   прежний документ без layout сохраняет своё представление.
3. Изменение текста, split/merge/delete/extract/remap: точные связи обновляются
   либо явно утрачивают актуальность, без молчаливого повторного использования.
4. Неверный FONT kind/face, dangling range/page/scene, offset вне текста,
   нечисловые/неконечные координаты и неверная размерность дают адресный отказ.
   Проверка face не подразумевает парсинг opaque шрифта: невозможность проверить
   реальный состав программы остаётся явной границей.
5. Квоты на границе, превышение и увеличенный пользовательский бюджет;
   отсутствие частичных записей и новых обязательных зависимостей.

Formats подключает только принятый публичный API. Отдельная приёмка PDF → Model →
JSON → PDF/DOCX должна сравнить исходную структуру и рендер независимого оригинала,
проверить правку и отчёт о неизвестных объектах. Закрытие этого контракта в Model
само по себе не закрывает C-PDF-01 или замену pdf2docx.
