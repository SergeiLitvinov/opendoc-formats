# Открытые задачи

Здесь перечислена только работа, которую ещё требуется реализовать или принять.
Текущее покрытие — в [разделах по форматам](../guide/format-audit.md),
проверки — в [описании корпуса](corpus.md), границы API — в
[реестре контрактов](format-requests.md#конечные-контракты).

Приоритет: C-PDF-01 и C-MAP-01, затем оставшиеся требования C-DOCX-01/02.
Каждая задача принадлежит OpenDoc Formats. Пробелы общего API согласовывать
[явным контрактом с OpenDoc](opendoc-proposals.md); парсеры, движки, измерения
и нативную приёмку оставлять в Formats.

## Приоритет P0: диагностика импорта (OF15)

- Обеспечить feature/location/severity и состояние semantic/opaque/visual/lost/rejected
  для каждого непереносимого объекта во всех читателях, включая EPUB и PDF.
- Дополнить инвентарь прямых legacy-читателей без богатой промежуточной модели
  непереносимыми объектами исходного файла. Для integration scenes/graphs/ranges
  раскрыть агрегатные оценки полей в оценки каждого исходного объекта и его связей.
  Границы текущей оценки — в [ресурсах](../guide/resources.md).
- C-MAP-01: автоматически подтверждать связи произвольных intermediate snapshots,
  полный инвентарь объектов и нативные сценарии произвольного split/merge.
- Приёмка: по fixture каждого непереносимого объекта issue указывает источник;
  JSON сохраняет provenance/расширения; отсутствие warnings не выдаётся за lossless.
  Различать отсутствующий backend, отмену и превышение лимитов.

## Общие лимиты и отмена (C-LIMIT-01, P1)

- Ограничить работу, память и ресурсы внутри каждого парсера и всех преобразований;
  бюджет структуры Model не считать бюджетом стороннего декодера.
- Добавить контрольные точки отмены в ещё не охваченные нативные маршруты
  и преобразования; определить прерываемые границы длительных сторонних
  вызовов там, где это допускает API движка.
- Приёмка: входной размер, nodes/depth/bytes/embedded bytes, работа внутри декодера,
  поздний отказ и отмена сохраняют исходник и назначение; квота и адрес ошибки явные.

## Препарирование и исходная совместимость

- C-DOCX-NATIVE-TEXT-01: принять версионированный wheel и повторить потребительскую
  проверку на прежних SHA реального корпуса; объяснить оставшиеся текстовые различия.
  Для `.rels` без владельца исследовать безопасное чтение с полной диагностикой
  либо подтвердить явный неподдерживаемый профиль. Не ослаблять ZIP/XML, лимиты
  и отмену; минимальную synthetic gate не считать полной заменой прежнего reader.
- В общем инспекторе Anatomy расширить валидацию полей деклараций, Id/Type,
  URI-нормализации и неподтверждённых OPC-профилей за пределами конечного физического
  аудита. Принять эти профили на независимых originals с явными отказами/диагностикой.
- Расширить EPUB inspection на `xml:base`, нормализацию и проверку внешних URL,
  неподтверждённые rendition/URI профили и полную диагностику повреждённого
  manifest; сохранять явные отказы и XML policy вне поддержанного профиля.
- Расширить сопоставление физического ZIP-инвентаря и импортированных OPC parts
  на PPTX и остальные пакетные форматы; подтвердить неизвестные компоненты
  и их зависимости независимыми оригиналами и нативной приёмкой.
- Разбирать внутренние streams/FAT/miniFAT OLE/CFBF-вложений, форматы шрифтов и
  медиа с контролем смещений, размеров и неизвестных полей; не исполнять объекты.
- Для PDF разобрать цепочку incremental revisions/xref/trailer Prev, поколения,
  исходные диапазоны и object streams. Отделять ремонт backend от исходной структуры.
- Принимать правки относительно независимых оригиналов по нативным структурам,
  бинарным payload и отображению в целевом приложении; расширить конечные fixtures
  на основные функции каждого формата. Буквальное совпадение адреса не считать
  доказательством semantic correspondence или полного C-MAP-01.

## Приоритет P1: чтение исходного LaTeX (OF04)

- Добавить таблицы, изображения, локальные input/include и bibliography/citations.
- Расширить преамбулу, пользовательские macros, короткие heading titles, chapter
  и уровни заголовков вне нативного профиля.
- Добавить numbered equation/align, labels/refs, расширенные math environments,
  Unicode math и семантическую проекцию MathML/OMML/FormulaTree в TeX.
- Поддержать формулы в подписях и других moving arguments вне заголовков,
  геометрию и стили вне выражения;
  расширить конечную math-грамматику с независимой структурной и визуальной приёмкой.
- Расширить текстовые индексы на вложения, порядок index/underline и переключение
  вложенного emphasis; определить точное представление пустых script scopes.
- Для списков добавить custom labels, стили маркеров и counter-программы;
  определить представление разорванных scopes и объектов вне текстового профиля.
- Заменить оставшийся DOCX-мост нативными маршрутами после приёмки каждого вида объектов.
- Ограничить раскрытие macros, циклы include, размер/глубину и чтение вне resource root;
  не исполнять TeX, shell escape или сетевые include.
- Приёмка: собственный .tex с .bib и изображением → OpenDoc → JSON → TeX;
  сравнить семантику, связи, source spans и исходное отображение. Отдельные fixtures
  для циклов, неизвестных пакетов и лимитов. Полноту произвольного программируемого
  TeX не объявлять без соответствующего покрытия.

## Приоритет P1: семантика сложного DOCX (OF05)

- Проверить обработку `w:t` без `xml:space`, явного default/preserve и наследования
  в Word. В независимом оригинале `After ` + hyperlink `Link` без preserve Word
  показывает `AfterLink`, а текущий rich reader сохраняет пробел. Согласовать
  исходный текст и его отображение, принять межформатный маршрут и два цикла.
- Разрешать отсутствующие native page settings явно: у независимого DOCX без
  `pgSz` импорт подставляет A4, а проверенный Word показывает Letter. Не считать
  defaults Model доказательством исходной геометрии; согласовать профиль defaults,
  unknown diagnostics и нативную/межформатную приёмку.
- C-FONT-OPAQUE-01: определить и проверить opaque-only font families/variants,
  каскад и пакетные footnotes/endnotes; подтвердить embedding и glyph coverage
  относительно оригинала без удаления FONT references и повышения бюджета LOSS.
- C-DOCX-03: расширить цветовой каскад на условные стили таблиц, RTL,
  неизвестные тематические объявления и добавление произвольных новых стилей.
- Расширить интервалы на остальные допустимые нативные значения и полный условный
  каскад абзаца; сравнить исходное оформление в Word.
- C-DOCX-05: проверить геометрию и внутренние отступы таблиц, внутритекстовое
  размещение и полный условный каскад. Сначала воспроизводимый дефект и два сравнения
  с оригиналом в Word, затем исправление и нативное редактирование.
- Разрешать font slots по Unicode/language/RTL; диагностировать отсутствующие
  и неизвестные темы; обеспечить перенос без зависимости от системных шрифтов конвертера.
- Для границ таблиц вычислять inherited/conditional styles и конфликты соседних
  границ, RTL start/end, визуальную нормализацию толщины Word и межформатное рисование.
- Реализовать семантические диапазоны комментариев/ответов, tracked changes
  с режимами отображения, fields/ссылочные поля и content controls.
- Расширить text boxes/SmartArt/embedded objects с документированным fallback:
  другие OLE classes/previews, native first/even content и нативные правки объектов
  в колонтитулах.
- Приёмка: DOCX → JSON → DOCX сохраняет IDs/диапазоны и неизменённые части;
  сравнить полные страницы с оригиналом и выполнить нативные правки.
  Для межформатных surrogate/opaque выдавать явный отчёт; соблюдать подписи,
  запрет исполнения макросов/содержимого и лимиты. Общий контракт Model запрашивать
  только при доказанном пробеле существующего API.

## Приоритет P1: семантика и graphics state PDF (OF07)

- Оценить совместимость PyMuPDF 2 отдельно: обязательные layout/ML зависимости,
  их лицензии, API и полную нативную приёмку; определить минимальный маршрут

- Расширить перенос flow-изображений на ячейки таблиц и разбиение одного
  смешанного абзаца с несколькими изображениями, не помещающимися на странице;
  подтвердить подписи и геометрию относительно независимого исходного рендера.
- C-PDF-01: связать нативные glyph observations с канонической моделью через
  [контракт C-TEXT-LAYOUT-01](text-layout-contract.md), сохраняя общие данные
  и validation в Model, а парсинг и paint evidence в Formats. Подключить принятый
  публичный API и проверить актуальность layout после правок. Завершить
  инвентаризацию исходных объектов; подтвердить reading order/OCR, Unicode/shaping, font-program
  bindings и полный visibility/clip state без эвристического восстановления неизвестного.
- Реконструировать полное дерево полей: orphan/inherited/default values,
  дополнительные actions, XFA/signatures/radio groups и полный annotation appearance.
  Расширить самостоятельный inspection text scope на appearances/clips/groups/layers
  и подтвердить ограничения работы/памяти внутри стороннего декодера.
- Добавить semantic structure tree, marked content/tagged PDF и optional content/layers.
- Реализовать полный clipping/masks/blend/transform, ICC/output intents,
  graphics state текста/изображений и source-object → fallback mapping.
- Расширить outline actions/named destinations и anchors остальных узлов.
- Поддержать полный профиль page boxes/UserUnit/inherited нестандартных областей;
  определить обработку legacy JSON без исходных media dimensions без догадок.
- Проецировать общие clip/group данные в нативном PDF writer; приёмка Word
  не заменяет проверку PDF.
- Приёмка: tagged PDF и PDF с формой, слоями и обтравкой → JSON → PDF;
  сравнить структуру и исходный рендер с явными допусками. Обозначать OCR/эвристики
  в provenance, не исполнять активные actions и не подменять текст reflow-проверкой.
