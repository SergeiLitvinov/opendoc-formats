# Руководство OpenDoc Formats

**Форматы. Структура. Переход.** Библиотека читает и записывает файлы через обязательную модель OpenDoc.
Начните с этого руководства; [форматы](formats.md), [ресурсы](resources.md),
[архитектура](architecture.md) и [расширения](extensions.md) описывают подробный контракт.

## Установка

`uv sync --all-extras` в самостоятельном checkout. Можно установить только нужные extras:
`uv sync --extra docx --extra html`. Базовый пакет требует только OpenDoc, тяжёлые движки загружаются лениво.
Официальный OpenDoc закреплён URL wheel в lockfile; соседние проекты не используются.
Для установки релизного wheel предоставьте также официальный wheel OpenDoc и выбранные движки;
точная команда находится на [главной странице](../index.md#установка).

## Импорт

`read_document(path, format_id=None, options=None)` выбирает обработчик по расширению.
Форматы: TXT, HTML/HTM, DOCX, EPUB, PDF, PPTX, DjVu и JSON OpenDoc.
`ImportResult.document` — DocumentModel; `issues` — диагностика. Неизвестный формат, отсутствие движка,
входной лимит, отмена или неверная модель возвращают результат без документа. Файловые ошибки и исключения
парсера не маскируются пустым успешным документом. Ограничения обработчика также находятся в metadata.

TXT сохраняет пустые строки; конечный `TextProfile` поддерживает UTF-8, UTF-16 LE/BE,
явный CP1251, BOM и исходные переводы строк. HTML/CSS не исполняет JavaScript и не загружает сеть.
DOCX/EPUB/PDF/PPTX сохраняют структуры, ресурсы и объяснимые fallback; непрозрачный XML/растр
не обещает полноценного редактирования объекта. DjVu поддерживает имеющийся текстовый сценарий через внешний движок.
JSON читает нативный стандарт OpenDoc; миграция файлов со схемой приложения принадлежит потребителю.

## Экспорт

`write_document(model, path, format_id=None, options=None)` возвращает ConversionReport OpenDoc.
Реестр поддерживает TXT, HTML, DOCX, PDF, PPTX, EPUB, DjVu, JSON и LaTeX (`.tex`).
EPUB экспортируется в опубликованном конечном профиле; DjVu-экспорт не заявляется.
Сначала проверяется модель и наличие движка; запись выполняется во временный файл.
Ошибка/отмена не заменяет прежний результат. После успеха временный файл публикуется атомарно.
Диагностику потерь необходимо читать даже при success=true. Проверка читаемости временного файла включена
по умолчанию (`verify_output=True`); её [границы](formats.md#проверка-результата) не означают визуальную или Office-приёмку.

Прямые обработчики `writers.docx_writer.write_docx_model`, `writers.pdf_writer.write_pdf_model`,
`writers.pptx_writer.write_pptx_model` и остальные сохранены; единый контракт дополнительной валидации/отмены
даёт реестр экспорта. Прямые PDF → DOCX-движки находятся в `writers.pdf_to_docx`.
`writers.pptx_to_html.convert` создаёт каталог автономного просмотрщика с CSS/JS и изображениями.

## LaTeX и Pandoc

`writers.text_render.render_latex(text=..., title=..., author=...)` собирает LaTeX из извлечённого текста,
заголовков, списков и таблиц. `render_latex_pandoc` использует внешний Pandoc с текстовым fallback.
`writers.docx_to_latex.DocxToLatexConverter` и `readers.latex.docx_to_latex` работают напрямую с DOCX;
`docx_to_latex_pandoc` поставляется вместе с Lua-фильтром очистки.
Экспорт модели в `.tex` использует DOCX-мост и сообщает `latex-layout`: точная геометрия, сложные объекты
и полное восстановление формул не гарантируются. Исходник TeX не компилируется этой библиотекой.
Полноценный импорт произвольного TeX в модель не поддерживается.

## Ресурсы, ограничения и OCR

ImportOptions.resource_root разрешает локальные HTML-ресурсы только внутри указанного корня; по умолчанию
доступ к локальным изображениям выключен. Входной предел — 10 MiB; HTML имеет такой же собственный предел.
DocumentLimits проверяются после парсинга; это не обещание ограничения памяти стороннего движка.
Отмена проверяется до/после парсинга и до публикации экспорта, не прерывает сторонний парсер внутри вызова.

PDF по умолчанию читает текстовый слой (`pdf_mode="fast"`). Режимы structure/scan принимают
`ocr_engine_factory` потребителя; встроенного OCR-движка и зависимости от приложения нет.
Фабрика принимает backend/use_gpu и возвращает движок с is_available и recognize_pdf_geometry.
При отсутствии запрошенного движка модель содержит предупреждение. Результаты OCR описаны типами
в readers.pdf_ocr_types, слияние — в readers.pdf_ocr_merge.

## Расширение и проверки

AdapterRegistry/AdapterSpec отвечают за импорт, ExporterRegistry/ExporterSpec — за экспорт.
default_registry()/default_exporter_registry() создают отдельные реестры без глобального состояния.
Обработчик импорта возвращает DocumentModel, экспорта — ConversionReport; повторные ID/суффиксы отклоняются.
requirements перечисляет импортируемые модули необязательного движка. Приложение может добавить свой адаптер.

Собственный корпус проверяет чтение/запись Office/PDF/HTML, формулы, диаграммы, ресурсы, шрифты,
повторные JSON-циклы, атомарность, ограничения и отсутствие приложения. Такие проверки не заменяют
ручную проверку правок в Word/PowerPoint. [Навигатор](../reference/code.md) создаётся из AST;
[проверенные возможности](format-audit.md) связывают обработчики с проверками.

## Извлечённый текст

`readers.text.extract_text` извлекает текст DOCX, `readers.fix_encoding.fix_encoding` исправляет кодировку файла. `writers.extracted_text.write_extracted_text` сохраняет готовый текст в TXT, DOCX или LaTeX. Источником может быть любой OCR-движок потребителя; библиотека не запускает распознавание самостоятельно.
