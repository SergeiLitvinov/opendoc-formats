# Композиция карт объектов

`get_object_mapping(report)` возвращает копию карты из общего JSON-контракта
OpenDoc. `compose_object_mappings(first, second, bridges, source=..., target=...)`
связывает два этапа преобразования. Типы, codec и проверка ссылок принадлежат
модели; вычисление композиции и измерение PDF — адаптеру.

## Явные связи между этапами

Ключ `bridges` — ID вхождения в `first.targets`; значение — tuple ID вхождений
в `second.sources`. Один ключ может вести к нескольким исходным вхождениям
(split); несколько ключей — к одному (merge). Связанные группы объединяются.
Одинаковый resource ID или одинаковые пиксели не устанавливают связь автоматически.

- Отсутствующий ключ или `None` означает неизвестную связь.
- `()` явно объявляет удаление. Вызывающая сторона должна подтвердить это
  своим сценарием редактирования; библиотека не выводит удаление из отсутствия связи.
- Неучтённый внешний источник в merge делает группу неизвестной и оценку неполной.
- Частичная потеря с сохранившимися targets имеет состояние `opaque` и `partial_loss`.
  Полное объявленное удаление имеет `lost` и пустой tuple targets.

```python
from opendoc_formats import compose_object_mappings, get_object_mapping, read_document, write_document

# first — карта предыдущего результата; middle прочитан именно из этого результата.
# original — исходный snapshot. В этом примере изображения не удалены и не раздвоены.
report = write_document(middle, "next.pdf")
second = get_object_mapping(report)
source_nodes = {item.node_id: item.id for item in second.sources if item.node_id}
bridges = {
    item.id: (source_nodes[item.node_id],) if item.node_id in source_nodes else None
    for item in first.targets
}
combined = compose_object_mappings(
    first, second, bridges, source=original, target=read_document("next.pdf").document,
)
```

PDF-импорт назначает каждому декодированному изображению typed anchor:
SHA-256 текущих PDF-байтов, номер страницы и номер нативного image block.
Повторные вхождения одного ресурса различаются; anchors сохраняются через JSON
и перестановку модели. После записи новых PDF-байтов адреса измеряются заново.
Пример допустим при известной связи intermediate snapshot с первым результатом;
само совпадение пользовательских ID не доказывает такую связь.

## Состояния и область ссылок

`visual` предыдущего этапа не становится `semantic` после последующей записи.
Ресурсы замены из промежуточного snapshot не копируются как ссылки на финальный
результат. Raster replacement с областью `target` создаётся только при подтверждении
соответствующего ресурса в переданном финальном snapshot. Без него визуальная
группа остаётся без такой замены, а оценка — неполной.

Композиция сохраняет область исходных объектов первого этапа; несвязанные группы
второго этапа не объявляются частью этой области. `assessment_complete` относится
к объявленным группам, а не ко всему инвентарю PDF. Ограничения: 10 000 вхождений,
групп и bridge keys на карту; суммарно 100 000 bridge edges.

Итоговая карта получает `result_id`, формат и состояние публикации второго этапа.
Внешний `ExportOptions.quality_gate` может поместить её общий JSON в
`report.metrics['object_mapping']`. Отказ очищает actual targets и target replacement;
прежний файл сохраняется. Проверка структуры и ссылок не аутентифицирует декларации
происхождения и не доказывает визуальную идентичность произвольного документа.

Подтверждены два полных PDF/JSON цикла, перестановка, явное удаление и отказ
по качеству. Split/merge проверены на явно объявленных отношениях.
Автоматическое доказательство связи произвольных файлов и полный инвентарь
объектов остаются в [TODO](../development/todo.md).
