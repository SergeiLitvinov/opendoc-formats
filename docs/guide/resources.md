# Ресурсы, лимиты и отмена

## Локальные и внешние ресурсы

По умолчанию HTML-импорт не открывает локальные изображения и не загружает сеть.
Data URI/SVG обрабатываются с ограничением размера и фильтрацией активного XML.
Локальный доступ нужно включить явно:

```python
from pathlib import Path
from opendoc_formats import ImportOptions, read_document

result = read_document("report.html", options=ImportOptions(resource_root=Path("assets")))
```

Пути разрешаются относительно `resource_root`, затем проверяется, что они остаются внутри корня.
Встроенные части DOCX/PPTX/EPUB читаются из самого пакета после проверки ZIP.
Внешние связи OOXML могут сохраняться как сведения; библиотека не загружает их содержимое.
Внешние программы запускаются только выбранными прямыми конвертерами.

## Где проверяются лимиты

`max_input_bytes` — положительное целое, по умолчанию 10 MiB. Реестр проверяет размер входного файла
перед вызовом обработчика. HTML имеет дополнительный фиксированный предел 10 MiB;
увеличение общего предела не отменяет это ограничение HTML.

Проверки ZIP центрального каталога отклоняют traversal, дублирующиеся имена и превышение
числа записей, заявленного распакованного размера и коэффициента сжатия.
Выбранные `DocumentLimits` передаются в integration чтения, JSON, валидацию,
экспорт и внутренние операции Model. Бюджет файловой инспекции задаётся через
keyword-only `options: ImportOptions`; SHA256 проверяется до и после измерения,
отмена отбрасывает его результат. Nodes/depth/bytes/embedded bytes имеют
расположенную диагностику quota/maximum, defaults не повышаются автоматически.
Эти проверки структуры не ограничивают память и время внутри стороннего парсера.
Для жёстких ограничений потребитель может изолировать операции в отдельном процессе.

Собственный PPTX 35 slides/6720 runs проходит два native/JSON цикла с
max_nodes=200000; default 100000 даёт адресный отказ. Большая модель шести
форматов принимается с 300000, частное представление большого DOCX — с 500000.
Поздний отказ и неизвестная квота backend сохраняют исходник и назначение.
Границы доказательств — в [бюджете инспекции](formats.md#бюджет-файловой-инспекции)
и [проверенных возможностях](format-audit.md#ресурсы-и-карты-объектов).

## Отмена

```python
from threading import Event
from opendoc_formats import ImportOptions, read_document

stop = Event()
result = read_document("report.pdf", options=ImportOptions(cancelled=stop.is_set))
```

Импорт проверяет отмену до чтения и после возврата парсера, затем отбрасывает результат при отмене.
Экспорт проверяет её до обработки, после записи и непосредственно перед атомарной заменой
(в том числе после проверки читаемости).
Собственный TeX parser проверяет отмену в ходе разбора. Богатый PDF-импорт передаёт
тот же callback в подготовку content view, геометрию/таблицы, растр/вектор,
OCR merge, шрифты, paint, interactions и scopes. Контрольные точки стоят между
страницами, этапами и отдельными объектами; отмена не превращается в OCR warning.
Формирование OCR preservation records также проверяет сигнал на каждом предупреждении;
частичный ledger не возвращается как завершённый импорт.
После нативного поиска таблиц PDF сигнал проверяется до обхода результата.
ArtifactLimitError/ResourceLimitError из анализатора не подменяются warning
и не запускают следующую стратегию после исчерпания бюджета.
То же правило действует для нативного извлечения векторов. Реконструкция таблиц
проверяет сигнал между ячейками и при сопоставлении текстовых блоков;
связывание diagnostic records с итоговым списком warnings — между записями.
HTML проверяет отмену при обходе узлов, списков и таблиц, вычислении CSS,
чтении локальных изображений и XML-ресурсов, привязке диагностики.
EPUB передаёт сигнал в чтение архива и XML пакета, главы, таблицы, CSS
и встроенные ресурсы. Отмена закрывает архив; исходные файлы не изменяются.
Это не гарантирует прерывания произвольного
стороннего вызова. Файловые ошибки и исключения импорта остаются исключениями;
диагностический результат не подменяет ошибку пустым успешным документом.

`read_document` возвращает `import.cancelled` без частичной модели также при
отмене внутри reader или при финальной проверке. Прямые PDF readers/helpers
с keyword-only `cancelled` выбрасывают `OperationCancelledError`, закрывая native
documents; source bytes и annotations не изменяются. Интерактивные appearances
удаляются только в несохраняемом content view. Неактивный callback сохраняет
полный JSON модели, включая текст, вектор, растр и annotations.

Прямые HTML/EPUB readers и `read_epub_package` также принимают keyword-only
`cancelled` и выбрасывают `OperationCancelledError`. Неактивный callback
сохраняет полный JSON HTML/EPUB. Повторный импорт после отмены проверен;
сигнал не входит в сериализуемую модель. Политики локальных ресурсов и сети
остаются обязательными независимо от отмены.

DOCX и PPTX принимают тот же keyword-only `cancelled` в богатых и текстовых
readers; `read_document` передаёт `ImportOptions.cancelled` внутрь богатого импорта.
DOCX проверяет сигнал при обходе package relationships, стилей, абзацев и runs,
полей, таблиц и вложенных ячеек, колонтитулов, изображений, шрифтов, групп,
provenance и диагностики. PPTX — между слайдами, внутри групп/фигур, абзацев/runs,
таблиц, ресурсов, тем и массивов диаграмм, а также при диагностике.
Разрешение цепочки стилей заголовка DOCX проверяет сигнал на каждом предке.
Контрольные точки после открытия backend и перед возвратом исключают выдачу
частичного документа при раннем или позднем сигнале.

Callback хранится в контексте одной синхронной операции Formats (`ContextVar`),
восстанавливается при завершении или исключении и изолирован между потоками.
Model, package parts и JSON не хранят сигнал. Вне явного контекста общие helpers
не активируют отмену. Прямые readers выбрасывают `OperationCancelledError`,
реестр возвращает `import.cancelled`; отсутствие сигнала сохраняет полный JSON.
Исходный ZIP не записывается; его целостность и повторное чтение проверены.
Открытие пакета сторонним backend, единичный разбор XML, декодирование или
сериализация Model остаются непрерываемыми вызовами. Это кооперативная отмена,
а не гарантия предельного времени или памяти процесса.

Нативные `write_docx_model` и `write_pptx_model` принимают keyword-only `cancelled`;
реестр передаёт в них `ExportOptions.cancelled`. Контрольные точки находятся в
обходе разделов/слайдов, текста, ячеек, групп, изображений, стилей и chart data,
подготовке шрифтов/цветов и восстановлении DOCX package relationships.
Восстановление OOXML проверяет сигнал между созданием частей пакета,
при индексации связей и обходе защищённых XML-деревьев.
Внутри одного объекта DOCX сигнал проверяется при размещении ячеек в сетке,
поиске свободных столбцов, заполнении rowspan, обходе физических продолжений
объединённой ячейки и подготовке/выводе векторной сцены. В PPTX проверяется
каждый элемент собираемой группы фигур или серии комбинированной диаграммы;
сигнал после создания группы или XML диаграммы обрабатывается до следующего этапа.
Отмена не подменяется предупреждением о повреждённом изображении или шрифте.
Прямой writer выбрасывает `OperationCancelledError`, `write_document` возвращает
неуспешный отчёт с feature `export.cancelled`.

Оба writer сначала сохраняют ZIP во временный файл. Сигнал проверяется после
сохранения и после копирования в соседний `.partial`, непосредственно перед
атомарной заменой назначения. Отмена удаляет промежуточные файлы и сохраняет
прежнее назначение и исходную модель. После успешной замены прямой writer уже
не опрашивает сигнал: позднее событие не выдаётся за выполненный rollback.
Реестр дополнительно проверяет свой staged результат перед публикацией.
Без сигнала полный JSON повторного импорта совпадает; собственные проверки
описаны в [корпусе](../development/corpus.md#отмена-нативного-экспорта-docx-и-pptx).
Сохранение ZIP и единичные вызовы Model/движков остаются отдельными
непрерываемыми этапами. PPTX staging не вводит новый
фиксированный предел размера выходного файла; выбранные лимиты Model сохраняются.

HTML, EPUB и TeX writers также принимают keyword-only `cancelled` напрямую
и через `ExportOptions`. HTML проверяет сигнал в normalize/resource/layout,
обходе блоков/ячеек/inline объектов, подготовке шрифтов и проверке навигации;
EPUB передаёт его вложенному HTML writer и проверяет XHTML callbacks, главы,
оглавление, metadata и архивные ресурсы. TeX проверяет блоки, runs, символы,
токены формул и scopes списков. Оставшийся DOCX-мост получает тот же сигнал,
обрабатывает временный `.tex` и публикует только завершённый результат.

В этих маршрутах отмена также даёт `OperationCancelledError` напрямую либо
feature `export.cancelled` в реестре. HTML проверяет сигнал после навигационной
проверки перед replace; EPUB и нативный TeX — после записи `.partial`.
Отмена сохраняет исходный JSON и прежнее назначение, удаляет временные файлы;
после успешного прямого commit ложный rollback не объявляется.
Неактивный callback сохраняет точные HTML/TeX bytes и содержимое всех частей
EPUB при фиксированном времени metadata. Условия безопасности XML и ресурсов,
конечные format profiles и существующие квоты не ослабляются. TeX не получает
новый фиксированный предел размера результата. Сигнал не хранится в Model;
одиночные системные/сторонние операции остаются непрерываемыми.

`writers.pdf_docx_model.prepare_pdf_docx` принимает keyword-only `cancelled`.
Без явного callback он наследует активный контекст DOCX writer; при прямом
вызове вне контекста отмена не активна. Подготовка работает с глубокой копией
модели. Контрольные точки покрывают ресурсы, typed paint/clip scopes, разделы,
строки и baseline shifts, таблицы и borders, images/vector paths, группы,
композицию прямоугольных областей, paint order и поворот страницы.
Отмена внутри векторного рендерера передаётся как `OperationCancelledError`,
закрывая его временный native document; она не подменяется ValueError о формате.
Проверка после валидации отбрасывает результат при позднем сигнале.

`PdfModelConverter` передаёт сигнал `ImportOptions` в экспорт, когда отдельные
`export_options` не заданы. Явные export options управляют своей стадией.
Неактивный callback сохраняет полный JSON частного Word view, включая ресурсы
и сцены. Это не расширяет принятую графическую проекцию: общая opacity, clipping
и другие неподдержанные варианты по-прежнему подчиняются прежнему quality gate.
`deepcopy`, отдельная Model operation и вызов native engine остаются неделимыми;
кооперативные проверки не являются жёстким ограничением времени/памяти.

## Отмена TXT

`read_txt`, `read_txt_model` и `write_txt_model` принимают keyword-only `cancelled`;
публичный реестр передаёт `ImportOptions.cancelled` и `ExportOptions.cancelled`.
Импорт проверяет сигнал после чтения/декодирования, при сборе разделителей строк
и между абзацами. Экспорт — внутри разделов, абзацев, runs и вложенных таблиц,
при восстановлении исходных переводов строк, после кодирования и перед заменой
готового файла. Частичная модель не выдаётся, прежнее назначение сохраняется.
Прямой вызов выбрасывает `OperationCancelledError`; реестр возвращает
`import.cancelled` либо `export.cancelled`. Контекст сигнала принадлежит Formats,
не попадает в Model/JSON и восстанавливается после завершения.
Неактивный callback сохраняет полный JSON и bytes профиля encoding/BOM/newlines.
Чтение файла, вызов кодека, regex scan между совпадениями, split/join и хеширование
остаются неделимыми вызовами; это кооперативная отмена без жёсткого time/memory bound.

## OCR для PDF

`pdf_mode` принимает `fast`, `structure`, `scan`. `fast` использует текстовый слой.
`structure` объединяет текстовый слой с OCR; `scan` выбирает OCR-содержимое.
Движок передаёт потребитель через `ocr_engine_factory(backend=..., use_gpu=...)`.
Он должен иметь `is_available` и `recognize_pdf_geometry(path, handwriting=...)`.
Результаты описаны в `readers.pdf_ocr_types`; слияние — в `readers.pdf_ocr_merge`.
При отсутствии запрошенного OCR предупреждение сохраняется в metadata модели.
Встроенный движок распознавания не поставляется.

В structure/scan отсутствие или недоступность движка, исключение распознавания
и отсутствие page results имеют явные warnings в богатом импорте и текстовом
`read_pdf_scenario`. Предупреждения отдельных OcrPageResult сохраняются в
metadata/публичных issues и повторном импорте JSON, в том числе когда страница
OCR не содержит блоков. Fast не инициализирует OCR и не сообщает о его отсутствии.
Оба маршрута сохраняют типизированные `pdf.ocr-unavailable`, `pdf.ocr-empty`,
`pdf.ocr-failed`, `pdf.ocr-provider-warning` с reason, source provenance и адресом
страницы, когда он известен. Неизвестное содержание сообщения провайдера имеет
состояние `opaque`; оно не классифицируется по тексту как конкретная потеря.

## Диагностика текстового представления

`Text.diagnostics` содержит исходные отрицательные оценки в общем `IntegrationModel`.
`Text.to_dict(limits=...)` добавляет поле `diagnostics` только при наличии оценок;
его envelope и codec принадлежат Model. `text_to_document` и
`document_to_text` принимают выбранные `DocumentLimits` и сохраняют диагностику
при переходе через Model/JSON. Повторяющиеся сообщения разных объектов остаются
отдельными записями. Строковые `warnings` сохраняются для совместимости.

Общий codec проверяет JSON-поля диагностики до копирования. Не-JSON значения
в extra/measurement дают `ValueError`, не вызывая пользовательский `__deepcopy__`
и не подменяя исходные данные. Вложенные JSON-контейнеры результата независимы
от источника; тип Python-подкласса контейнера частью транспорта не является.

Текстовый PDF fallback различает сбой backend, сбой страницы, отсутствие backend,
отсутствие извлечённого содержимого и очистку некорректного декодирования pypdf.
Нативные ошибки анализа таблиц сохраняются и после геометрической интерпретации.
Отмена и превышение лимитов прекращают fallback; они не становятся warnings.
Проверки отмены выполняются между движками, страницами и семантическими блоками;
сам сторонний вызов извлечения остаётся неделимым. Табличный результат без plain
text также считается результатом чтения.

Отсутствующий backend HTML/EPUB и отказ, timeout либо пустой hidden text DjVu
имеют типизированную source-only диагностику. При построении текстового view из
богатой модели переносится отрицательная исходная диагностика и известные
metadata warnings. Непроверенные строковые warnings получают `opaque` с reason
`legacy-warning-unassessed`; это не оценка конкретного потерянного объекта.
Прежний `node_id` сохраняется как исходный адрес в record extra, без ссылки на
несуществующий узел нового view. Положительные `semantic` claims и графовые связи
богатого документа не переносятся. `assessment_complete` всегда false.

При Model → Text обходятся структурные occurrences, включая headers/footers,
footnotes и вложенные таблицы. Оценки `legacy.*` с состоянием `lost` указывают
изображения/ресурсы, формулы, ссылки, стили, границы inline runs, объединения ячеек,
геометрию, visual surrogates, section boundaries и отброшенные metadata/properties.
Указывается `source_model_path` и доступный исходный provenance. Его история
сохраняется в записи потери самого provenance, без копирования большой истории
для каждого отдельного отброшенного свойства. Integration graph fields имеют
агрегатную оценку; неизвестные внешние envelope fields явно отмечаются как потери.
Unknown integration extra сохраняется и при отсутствии исходных отрицательных записей.

Текст вложенных таблиц, block/inline формул и alt text изображений входит в строку
исходной ячейки. Их богатая структура имеет отдельные оценки потерь. Основные
таблицы представлены позиционными `BlockType.TABLE` и списком `Text.tables`:
`meta.table_index` явно связывает occurrence со списком, `meta.rows` содержит
совместимую копию. Обратный адаптер сохраняет порядок, не добавляет такую таблицу
повторно и отвергает конфликтующие/неверные ссылки. Редактировать таблицу можно
через разделяемые rows в памяти; при независимых копиях обе должны согласовываться.
Без явной ссылки отдельные `Text.tables` остаются отдельными occurrences;
совпадение значений не считается доказательством идентичности.

Адаптеры принимают `cancelled`, наследуют внешний контекст и проверяют выбранный
Model budget; исходник не меняется. HTML legacy wrapper передаёт limits/cancelled
и в импорт, и в проекцию. Обратное построение и неделимые Model/native calls
не являются жёсткой квотой работы/памяти; полные native budgets остаются в TODO.
Прямые legacy-читатели без богатой модели и отдельные члены integration graphs
ещё требуют полного попредметного инвентаря. Богатый PDF → DOCX продолжает
использовать DocumentModel напрямую.
