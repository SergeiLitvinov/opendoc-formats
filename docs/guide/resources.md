# Ресурсы, лимиты и отмена

## Локальные и внешние ресурсы

По умолчанию HTML-импорт не открывает локальные изображения и не загружает сеть.
Data URI/SVG обрабатываются с ограничением размера и фильтрацией активного XML.
Локальный доступ нужно включить явно:

```python
from pathlib import Path
from opendoc_formats import ImportOptions, read_document

result = read_document("report.html", options=ImportOptions(resource_root=Path("assets")))
```

Пути разрешаются относительно `resource_root`, затем проверяется, что они остаются внутри корня.
Встроенные части DOCX/PPTX/EPUB читаются из самого пакета после проверки ZIP.
Внешние связи OOXML могут сохраняться как сведения; библиотека не загружает их содержимое.
Внешние программы запускаются только выбранными прямыми конвертерами.

## Где проверяются лимиты

`max_input_bytes` — положительное целое, по умолчанию 10 MiB. Реестр проверяет размер входного файла
перед вызовом обработчика. HTML имеет дополнительный фиксированный предел 10 MiB;
увеличение общего предела не отменяет это ограничение HTML.

Проверки ZIP центрального каталога отклоняют traversal, дублирующиеся имена и превышение
числа записей, заявленного распакованного размера и коэффициента сжатия.
Выбранные `DocumentLimits` передаются в integration чтения, JSON, валидацию,
экспорт и внутренние операции Model. Бюджет файловой инспекции задаётся через
keyword-only `options: ImportOptions`; SHA256 проверяется до и после измерения,
отмена отбрасывает его результат. Nodes/depth/bytes/embedded bytes имеют
расположенную диагностику quota/maximum, defaults не повышаются автоматически.
Эти проверки структуры не ограничивают память и время внутри стороннего парсера.
Для жёстких ограничений потребитель может изолировать операции в отдельном процессе.

Собственный PPTX 35 slides/6720 runs проходит два native/JSON цикла с
max_nodes=200000; default 100000 даёт адресный отказ. Большая модель шести
форматов принимается с 300000, частное представление большого DOCX — с 500000.
Поздний отказ и неизвестная квота backend сохраняют исходник и назначение.
Границы доказательств — в [бюджете инспекции](formats.md#бюджет-файловой-инспекции)
и [проверенных возможностях](format-audit.md#ресурсы-и-карты-объектов).

## Отмена

```python
from threading import Event
from opendoc_formats import ImportOptions, read_document

stop = Event()
result = read_document("report.pdf", options=ImportOptions(cancelled=stop.is_set))
```

Импорт проверяет отмену до чтения и после возврата парсера, затем отбрасывает результат при отмене.
Экспорт проверяет её до обработки, после записи и непосредственно перед атомарной заменой
(в том числе после проверки читаемости).
Собственный TeX parser проверяет отмену в ходе разбора; PDF передаёт её внутрь
поддержанных нативных операций. Это не гарантирует прерывания произвольного
стороннего вызова. Файловые ошибки и исключения импорта остаются исключениями;
диагностический результат не подменяет ошибку пустым успешным документом.

## OCR для PDF

`pdf_mode` принимает `fast`, `structure`, `scan`. `fast` использует текстовый слой.
`structure` объединяет текстовый слой с OCR; `scan` выбирает OCR-содержимое.
Движок передаёт потребитель через `ocr_engine_factory(backend=..., use_gpu=...)`.
Он должен иметь `is_available` и `recognize_pdf_geometry(path, handwriting=...)`.
Результаты описаны в `readers.pdf_ocr_types`; слияние — в `readers.pdf_ocr_merge`.
При отсутствии запрошенного OCR предупреждение сохраняется в metadata модели.
Встроенный движок распознавания не поставляется.
